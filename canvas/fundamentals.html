2.1 Canvas 基础绘图 ​

Canvas 是浏览器提供的一块"位图画板"：JS 通过 2D 上下文下达一条条绘制指令，画完即与画布融为一体。本页把上手 Canvas 所需的最小集合讲全——上下文获取、状态机、路径与样式、渐变、文本、drawImage 与离屏画布，并用两个交互演示把它们串起来。

概念解析 ​

Canvas 是什么 ​

canvas 元素本质上是一块可以被 JS 任意涂写的位图：它有两套尺寸——canvas.width 与 canvas.height 决定位图本身的像素总量，CSS 宽高决定它在页面上显示多大，两者的脱节正是坐标系与 DPR 一页讲过的"画布发糊"问题的根源。getContext('2d') 返回的上下文对象是唯一的画笔，所有绘制都通过它完成。

Canvas 属于立即模式绘图：每条指令画完即忘，画布上没有"图形对象"的概念，想改一只圆的位置，只能把整块画布重画一遍。这与 SVG 的保留模式（节点常驻、改属性即更新）构成根本分野，后面的选型章节会专门对比。

为什么要有这样一块画板 ​

浏览器排版引擎擅长布局与文字，但不擅长"每一帧都重画几万个像素"。Canvas 把像素级的控制权交给 JS：形状、颜色、混合、逐像素运算都由代码决定，浏览器只负责把位图贴上屏幕。当图元数量大到 DOM 与 SVG 的节点管理成本失控时，Canvas 就是那个兜底的出口。

典型应用场景 ​

  • 数据可视化图表：高性能图表库（如 ECharts）的渲染引擎底层就是 Canvas；
  • 图像处理：滤镜、裁切、水印、像素级调色，配合 getImageData 完成；
  • 游戏与特效：粒子系统、精灵动画、小游戏的整屏绘制；
  • 签名板、画图工具：鼠标轨迹的连续绘制，天然契合立即模式。

核心 API 与原理 ​

获取 2D 上下文与高清适配 ​

js
// 高清三步法：在 onMounted 或首次绘制前执行（回扣 1.2 页）
const dpr = window.devicePixelRatio || 1
canvas.width = Math.round(canvas.clientWidth * dpr) // 位图尺寸乘 DPR
const ctx = canvas.getContext('2d')
ctx.setTransform(dpr, 0, 0, dpr, 0, 0) // 坐标系缩放回 CSS 像素
// 此后所有绘制代码都按 CSS 逻辑像素书写，无需关心 DPR

本章节所有组件都遵循这套三步法，并监听 window 的 resize 事件重建位图。

状态机模型：save 与 restore ​

上下文维护着一个状态栈：fillStyle、strokeStyle、lineWidth、font、阴影、变换矩阵等统统属于状态。save() 把当前状态压栈，restore() 弹栈还原。这是 Canvas 最重要的工程习惯——临时改状态前 save，用完 restore，函数之间就互不污染：

js
ctx.save()
ctx.fillStyle = '#d9564f'
ctx.translate(50, 0)
ctx.fillRect(0, 0, 40, 40)
ctx.restore() // 颜色与位移全部还原，后续绘制不受影响

不配对的 save/restore 是状态泄漏的主要来源：某处改了 lineWidth 忘了还原，十次调用之后整张图的线宽都变得不可预期。

矩形与路径 ​

矩形有三个直给 API：fillRect(x, y, w, h) 填充、strokeRect 描边、clearRect 擦除成透明，注意参数是左上角坐标加宽高，不是两个对角点。复杂形状则走路径体系：

js
ctx.beginPath()      // 开启新路径并清空旧路径——最常被遗忘的一步
ctx.moveTo(20, 20)   // 提笔到起点，不画线
ctx.lineTo(100, 20)  // 画线到目标点
ctx.lineTo(100, 100)
ctx.closePath()      // 回到起点闭合（fill 前建议显式调用）
ctx.fill()           // 或 stroke()：路径只是骨架，填充/描边才上色

关键心智模型：beginPath 之后的所有 moveTo、lineTo、arc 都在攒一条路径，直到 fill 或 stroke 才真正落笔。忘记 beginPath，新指令会叠加到旧路径上，前一个图形被莫名其妙再描一遍。

圆弧与贝塞尔曲线 ​

js
// arc：圆心、半径、起止角（弧度）、是否逆时针
ctx.arc(cx, cy, r, 0, Math.PI * 2) // 整圆
ctx.arcTo(x2, y2, x3, y3, r)       // 过两个切点的公切圆弧，常用于圆角矩形
ctx.quadraticCurveTo(cpx, cpy, x, y) // 二次贝塞尔：一个控制点，适合简单弧线
ctx.bezierCurveTo(c1x, c1y, c2x, c2y, x, y) // 三次贝塞尔：两个控制点，可表达 S 形

贝塞尔的控制点不在曲线上，它像磁铁一样把曲线"吸"过去；控制点决定弯曲方向与强度。圆角、平滑折线、连接线绕行，都是这四个 API 的排列组合。

填充、描边与渐变 ​

js
ctx.fillStyle = '#2f7ae5' // 填充颜料：颜色或渐变对象
ctx.strokeStyle = 'rgba(0, 0, 0, 0.4)'
ctx.lineWidth = 2
ctx.lineCap = 'round'  // 线端样式：butt | round | square
ctx.lineJoin = 'round' // 转角样式：miter | round | bevel

// 线性渐变：起点与终点定义渐变轴，色标挂在 0~1 的位置上
const lg = ctx.createLinearGradient(x0, y0, x1, y1)
lg.addColorStop(0, '#2f7ae5')
lg.addColorStop(1, '#8a63d2')
// 径向渐变：内圆到外圆之间插值，常做柔光与光晕
const rg = ctx.createRadialGradient(cx, cy, r0, cx, cy, r1)

要建立一个反直觉的认知：渐变对象是"颜料"，不是"图形"。它定义在一块与画布对齐的坐标空间里，之后谁用这个颜料谁被染色——把同一个渐变赋给 fillStyle 再平移坐标系画圆，渐变不会跟着圆跑。这正是"渐变圆"演示里每次点击都新建渐变的原因。

文本绘制与基线对齐 ​

js
ctx.font = 'bold 16px sans-serif'
ctx.textAlign = 'center'    // 水平对齐：left | center | right
ctx.textBaseline = 'middle' // 垂直对齐基准线
ctx.fillText('你好 Canvas', x, y)
ctx.strokeText('描边文字', x, y)
const w = ctx.measureText('你好 Canvas').width // 量宽，用于铺提示条底色

文本最大的坑在基线：fillText 的 y 参数指的不是文字顶部，而是当前 textBaseline 指定的基准线，默认 alphabetic（拉丁字母的基线）。默认值下"想让文字垂直居中在某条线上"必然偏移，中文场景尤其明显。经验法则：标签类文字显式设 middle 配合居中坐标，标题类设 alphabetic 并按排版习惯给 y。

drawImage 与离屏画布 ​

drawImage 有三种形态，参数逐级增多：

形态签名用途
原图绘制drawImage(img, x, y)按图片原始尺寸贴到指定位置
缩放绘制drawImage(img, x, y, w, h)指定目标宽高，整体缩放
裁切绘制drawImage(img, sx, sy, sw, sh, dx, dy, dw, dh)源图上裁一块，缩放画到目标矩形

九参数形态的记忆法：前四个数描述"从哪裁"，后五个数描述"画到哪"。

图片来源可以是 canvas 元素本身——document.createElement('canvas') 创建的离屏画布就是最常用的程序化"图片"：先用普通绘制指令在上面画好内容，再当作 img 传给 drawImage。它不见 DOM，可以反复复用，是下一页"离屏缓存"优化与图像滤镜的基础设施。

完整代码示例 ​

第一个演示是一块交互绘图板：切换模式后点击画布，在点击坐标处绘制矩形、圆、循环算顶点的星形或径向渐变圆，已画内容持续保留，可一键清空。

当前模式：矩形，点击画布在点击处绘制

试试：连续切换四种模式在画布各处点击，观察星形如何由十个顶点交替内外半径连成；点几下"渐变圆"叠出柔光层，再按"清空"复位。

核心代码与组件逻辑一致，可直接复制复用：

vue
// 文件: docs/.vitepress/components/canvas/CanvasShapes.vue
<template>
  <div class="demo-card">
    <div class="stage">
      <canvas ref="canvasRef" @click="onClick"></canvas>
    </div>
    <div class="control-row">
      <button
        v-for="m in modes"
        :key="m.key"
        class="ctrl-btn"
        :class="{ active: mode === m.key }"
        v-text="m.label"
        @click="mode = m.key"
      ></button>
      <button class="ctrl-btn danger" @click="clearAll">清空</button>
      <p class="tip">当前模式：<span v-text="modeLabel"></span>，点击画布在点击处绘制</p>
    </div>
  </div>
</template>
<script setup>
import { ref, computed, onMounted, onBeforeUnmount } from 'vue'
const modes = [
  { key: 'rect', label: '矩形' },
  { key: 'circle', label: '圆' },
  { key: 'star', label: '星形' },
  { key: 'grad', label: '渐变圆' },
]
const mode = ref('rect')
const modeLabel = computed(() => modes.find((m) => m.key === mode.value).label)
const canvasRef = ref(null)
let ctx = null
let cssW = 0
let cssH = 0
let shapes = [] // 已绘制图形的描述列表：点击时追加，resize 后据此完整重绘
const PALETTE = ['#2f7ae5', '#f0a020', '#3fa96f', '#d9564f', '#8a63d2']
const SIZE = 30 // 图形基准半径（逻辑像素）

// 计算星形顶点：外接圆半径 R 与内切圆半径 r 交替取样，从正上方开始
function starPoints(cx, cy, spikes, R, r) {
  const pts = []
  const step = Math.PI / spikes
  for (let i = 0; i < spikes * 2; i++) {
    const rad = i % 2 === 0 ? R : r
    const angle = -Math.PI / 2 + step * i
    pts.push([cx + Math.cos(angle) * rad, cy + Math.sin(angle) * rad])
  }
  return pts
}
function drawShape(s) {
  ctx.save()
  if (s.mode === 'rect') {
    ctx.fillStyle = s.color
    ctx.fillRect(s.x - s.size, s.y - s.size * 0.62, s.size * 2, s.size * 1.24)
  } else if (s.mode === 'circle') {
    ctx.beginPath()
    ctx.arc(s.x, s.y, s.size, 0, Math.PI * 2)
    ctx.fillStyle = s.color
    ctx.fill()
  } else if (s.mode === 'star') {
    const pts = starPoints(s.x, s.y, 5, s.size, s.size * 0.45)
    ctx.beginPath()
    ctx.moveTo(pts[0][0], pts[0][1])
    for (let i = 1; i < pts.length; i++) {
      ctx.lineTo(pts[i][0], pts[i][1])
    }
    ctx.closePath() // 闭合路径再填充，才能得到完整星形
    ctx.fillStyle = s.color
    ctx.fill()
  } else {
    // 径向渐变圆：中心实色、边缘透明，形成柔光点
    const g = ctx.createRadialGradient(s.x, s.y, 2, s.x, s.y, s.size)
    g.addColorStop(0, s.color)
    g.addColorStop(1, 'rgba(47, 122, 229, 0)')
    ctx.beginPath()
    ctx.arc(s.x, s.y, s.size, 0, Math.PI * 2)
    ctx.fillStyle = g
    ctx.fill()
  }
  ctx.restore()
}

function draw() {
  if (!ctx) return
  ctx.fillStyle = '#ffffff'
  ctx.fillRect(0, 0, cssW, cssH)
  shapes.forEach(drawShape)
}
// 点击画布：把鼠标事件坐标换算为画布逻辑坐标，追加图形并重绘
function onClick(evt) {
  const rect = canvasRef.value.getBoundingClientRect()
  shapes.push({
    mode: mode.value,
    x: evt.clientX - rect.left,
    y: evt.clientY - rect.top,
    size: SIZE,
    color: PALETTE[shapes.length % PALETTE.length],
  })
  draw()
}
function clearAll() {
  shapes = []
  draw()
}
// 高清三步法：位图尺寸乘 DPR、setTransform 缩放坐标系、CSS 尺寸交给样式表
function setupCanvas() {
  const cv = canvasRef.value
  const dpr = window.devicePixelRatio || 1
  cssW = cv.clientWidth
  cssH = cv.clientHeight
  cv.width = Math.round(cssW * dpr)
  cv.height = Math.round(cssH * dpr)
  ctx = cv.getContext('2d')
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0)
  draw() // 重设位图会清空内容，用 shapes 列表恢复
}
function onResize() {
  setupCanvas()
}
onMounted(() => {
  setupCanvas()
  window.addEventListener('resize', onResize)
})
onBeforeUnmount(() => {
  window.removeEventListener('resize', onResize)
})
</script>

上方为渐变填充 + 描边 + 阴影的样式文字；下方是离屏 canvas 程序化生成的源图与 drawImage 三种典型用法（红色虚线框标出九参数用法实际裁切的源区域）。

核心代码与组件逻辑一致，可直接复制复用：

vue
// 文件: docs/.vitepress/components/canvas/CanvasTextImage.vue
<template>
  <div class="demo-card">
    <div class="stage">
      <canvas ref="canvasRef"></canvas>
    </div>
    <p class="tip">上方：渐变填充 + 描边 + 阴影的样式文字；下方：离屏 canvas 程序化生成的源图与 drawImage 三种用法（红色虚线框为九参数用法的源区域）。</p>
  </div>
</template>

<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'
// 设计坐标系固定为 720x448，实际宽度按比例映射，类似 SVG viewBox 的思路
const VIEW_W = 720
const VIEW_H = 448
const IMG_W = 400
const IMG_H = 240
const canvasRef = ref(null)
let ctx = null
let off = null // 离屏 canvas：程序化生成的"图片"

// 在离屏画布上生成 400x240 的"照片"：渐变天空 + 太阳 + 山丘 + 水印
function buildSource() {
  off = document.createElement('canvas')
  off.width = IMG_W
  off.height = IMG_H
  const o = off.getContext('2d')
  // 渐变背景：深蓝过渡到暖橙
  const g = o.createLinearGradient(0, 0, 0, IMG_H)
  g.addColorStop(0, '#274b8f')
  g.addColorStop(0.55, '#4f83c2')
  g.addColorStop(1, '#f0b46a')
  o.fillStyle = g
  o.fillRect(0, 0, IMG_W, IMG_H)
  // 太阳：径向渐变圆，中心亮、边缘融入天空
  const sun = o.createRadialGradient(300, 80, 4, 300, 80, 46)
  sun.addColorStop(0, 'rgba(255, 236, 170, 1)')
  sun.addColorStop(1, 'rgba(255, 200, 90, 0)')
  o.fillStyle = sun
  o.beginPath()
  o.arc(300, 80, 46, 0, Math.PI * 2)
  o.fill()
  // 两座三角形"山"，closePath 闭合后填充
  o.fillStyle = '#2e5d3f'
  o.beginPath()
  o.moveTo(0, IMG_H)
  o.lineTo(130, 120)
  o.lineTo(260, IMG_H)
  o.closePath()
  o.fill()
  o.fillStyle = '#3e7a52'
  o.beginPath()
  o.moveTo(160, IMG_H)
  o.lineTo(300, 150)
  o.lineTo(440, IMG_H)
  o.closePath()
  o.fill()
  o.font = 'bold 22px sans-serif'
  o.fillStyle = 'rgba(255, 255, 255, 0.75)'
  o.fillText('离屏 canvas 生成 400x240', 16, 34)
}
// 样式文字：渐变填充 + 描边 + 阴影，阴影放在 save/restore 之间避免污染
function drawText() {
  ctx.save()
  ctx.font = 'bold 34px sans-serif'
  ctx.textAlign = 'center'
  ctx.shadowColor = 'rgba(31, 41, 55, 0.35)'
  ctx.shadowBlur = 8
  ctx.shadowOffsetY = 4
  const g = ctx.createLinearGradient(200, 0, 520, 0)
  g.addColorStop(0, '#2f7ae5')
  g.addColorStop(1, '#8a63d2')
  ctx.fillStyle = g
  ctx.fillText('Canvas 文字与图像绘制', VIEW_W / 2, 52)
  ctx.restore()
  ctx.font = '13px sans-serif'
  ctx.fillStyle = '#8a93a3'
  ctx.fillText('线性渐变填充 + 描边 + 阴影（阴影用 save/restore 包裹，用完即恢复）', VIEW_W / 2, 78)
}
function label(text, x, y) {
  ctx.font = '13px sans-serif'
  ctx.fillStyle = '#57606a'
  ctx.textAlign = 'left'
  ctx.fillText(text, x, y)
}
// drawImage 的三种典型用法
function drawImageDemos() {
  // 文字区与图像区的分隔线
  ctx.strokeStyle = '#d3d9e3'
  ctx.lineWidth = 1
  ctx.beginPath()
  ctx.moveTo(12, 94.5)
  ctx.lineTo(VIEW_W - 12, 94.5)
  ctx.stroke()
  // 用法一：三个参数，按图片原始尺寸放置到指定位置
  label('用法一：drawImage(img, x, y) 原图尺寸', 12, 110)
  ctx.strokeStyle = '#d3d9e3'
  ctx.strokeRect(12.5, 118.5, IMG_W, IMG_H)
  ctx.drawImage(off, 12, 118)
  // 用法二：五个参数，指定目标宽高整体缩放
  label('用法二：指定宽高缩放', 456, 110)
  ctx.strokeRect(456.5, 118.5, 240, 144)
  ctx.drawImage(off, 456, 118, 240, 144)
  // 用法三：九个参数——前四个数裁源区域 (sx, sy, sw, sh)，后五个数画目标矩形
  label('用法三：九参数裁切绘制', 456, 284)
  ctx.drawImage(off, 100, 60, 200, 120, 456, 286, 240, 144)
  ctx.strokeStyle = '#d9564f'
  ctx.setLineDash([5, 4])
  ctx.strokeRect(100.5, 60.5, 200, 120) // 在源图上标出被裁切的区域
  ctx.setLineDash([])
}
function draw() {
  if (!ctx) return
  ctx.fillStyle = '#ffffff'
  ctx.fillRect(0, 0, VIEW_W, VIEW_H)
  drawText()
  drawImageDemos()
}
// 高清适配：setTransform 同时写入 DPR（清晰度）与 设计宽/实际宽（等比铺满容器）
function setupCanvas() {
  const cv = canvasRef.value
  const dpr = window.devicePixelRatio || 1
  const cssW = cv.clientWidth
  const cssH = cv.clientHeight
  cv.width = Math.round(cssW * dpr)
  cv.height = Math.round(cssH * dpr)
  ctx = cv.getContext('2d')
  const k = cssW / VIEW_W
  ctx.setTransform(dpr * k, 0, 0, dpr * k, 0, 0)
  draw()
}
function onResize() {
  setupCanvas()
}
onMounted(() => {
  buildSource()
  setupCanvas()
  window.addEventListener('resize', onResize)
})
onBeforeUnmount(() => {
  window.removeEventListener('resize', onResize)
})
</script>

最佳实践与常见坑 ​

  • 每次画新图形前先 beginPath：路径是累积的，漏掉这一步会把上一次的路径连同新图形一起 fill 或 stroke，出现"重影"和莫名其妙的连线；把 beginPath 放在每个绘制函数的第一行是最低成本的纪律；
  • save/restore 必须严格配对：状态栈是全局唯一的，一个函数里 save 后在另一个分支提前 return，状态就永久泄漏，后面的绘制全部带病运行；临时状态的作用域最好限制在同一个函数体内；
  • 别把渐变当成图形的一部分：渐变颜料定义在画布坐标系上，不随图形移动；需要"每个图形自带渐变"时，为每个位置新建渐变对象（本页渐变圆的做法），或者利用"颜料不动图形动"的特性做视差效果；
  • 文字永远显式设置 textBaseline：默认 alphabetic 基线对不同字体、不同字号的表现不一致，中文场景下想当然地用 y 当"文字顶部坐标"几乎必然偏移；配合 measureText 量宽，才能把文字精确放进底色条里；
  • resize 后重设位图会清空画布：canvas.width 被赋值的那一刻（哪怕值不变）整个位图归零，所以重设尺寸后必须重绘；要么保存图形描述列表重画（本页绘图板的做法），要么把复杂背景缓存到离屏画布再 drawImage 回来；
  • 深色模式下主动铺底色：画布位图默认全透明，绘制代码若假设白底，深色主题里深色文字会直接隐身；本页所有组件第一步都 fillRect 一层底色，就是为了让演示在两种主题下都可读。

小结 ​

要点回顾：Canvas 是立即模式的位图画板，高清的前提是位图尺寸乘 DPR 并用 setTransform 缩放坐标系；上下文是状态机，save/restore 管理状态栈；矩形直给、路径攒骨架，beginPath 与 closePath 是路径体系的纪律；渐变是绑在坐标空间上的颜料；文本对齐看 textBaseline；drawImage 三形态与离屏画布构成"程序化图片"的完整闭环。
