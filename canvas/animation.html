2.2 动画与性能优化 ​

让画布动起来只需一个循环：每帧擦掉重画。但"能动"与"流畅"之间隔着一整套工程学问——与显示器刷新同步的 requestAnimationFrame、按真实耗时补偿的 delta time、以及应对大规模图元的性能四板斧。本页用一场 1000 个球的压力测试和一次逐像素滤镜实战把这套知识落地。

概念解析 ​

动画的本质：每秒三十到六十次的"翻页" ​

Canvas 上没有"动画对象"，动画就是快速重绘的错觉：每帧先清除或覆盖上一帧的画面，再按最新状态画一遍，只要每秒重复 30 次以上，人眼就把它理解成连续运动。因此动画程序的全部结构可以浓缩成一句话——"维护一批随时间变化的状态，加一个每帧重绘的循环"。

requestAnimationFrame 是什么 ​

rAF 是浏览器提供的"下一帧回调"接口：告诉浏览器"下一帧刷新前请调用我这个函数"。它与 setTimeout 的本质差异在于调度权：

  • 与显示器刷新同步：60Hz 屏幕上大约每 16.7ms 回调一次，90Hz、120Hz 屏上自动加密，节奏永远与硬件对齐；
  • 页面隐藏时自动暂停：切换标签页或最小化窗口后浏览器停止回调，回来后继续——既省电，也意味着恢复瞬间的时间差可能很大，必须由代码封顶处理；
  • 与 setTimeout 的差异：定时器只保证"不早于"指定毫秒执行，最小间隔还受嵌套限制钳制（约 4ms），既可能与刷新错拍造成撕裂感，也在页面隐藏时照跑不误，浪费资源。

典型应用场景 ​

  • 物理模拟与粒子系统：每帧积分位置、检测碰撞，下一页实战会完整实现；
  • 图表入场与过渡动画：柱子生长、曲线描画，配合缓动函数；
  • 游戏帧循环：逻辑更新与渲染更新都在同一次回调内完成；
  • 逐像素处理：滤镜、绿幕抠像、热力图渲染，属于"低频但重"的像素运算。

核心 API 与原理 ​

标准帧循环与 delta time ​

js
let rafId = 0
let last = performance.now()
function frame(now) {
  const raw = now - last // 本帧距上帧的真实毫秒数
  last = now
  // 封顶 33ms：标签页切走再回来时，raw 可能大到几百毫秒，
  // 不封顶的话物体一步跨出边界；33ms 约等于"最多当掉两帧"
  const dt = Math.min(raw, 33) / 1000
  update(dt) // 用 dt 推进状态：x += vx * dt
  draw()
  rafId = requestAnimationFrame(frame)
}
rafId = requestAnimationFrame(frame)

两个关键点：其一，一切运动量必须乘以 dt——高刷屏与低刷屏上每秒的位移才一致，这叫以时间为基准而非以帧为基准；其二，帧循环的句柄 rafId 要存下来，卸载时 cancelAnimationFrame(rafId)，VitePress 站点切页不清理的话，旧动画会在后台永远空转。

简单物理：速度、加速度与边界反弹 ​

不需要物理引擎，高中物理就够用：

js
// 匀速 + 边界反弹：撞墙时把对应速度分量取反
b.x += b.vx * dt
b.y += b.vy * dt
if (b.x < b.r) { b.x = b.r; b.vx = Math.abs(b.vx) }
if (b.x > W - b.r) { b.x = W - b.r; b.vx = -Math.abs(b.vx) }
// 加速度（如重力或吸引力）：先改速度，再改位置
b.vy += G * dt

位置夹回边界再加速度取反，是"不粘墙"的写法：直接让速度取反而不修正位置，球会在墙里抖动。更进阶的吸引、阻尼、限速，下一页粒子系统会用到。

性能四板斧 ​

  1. 离屏 canvas 缓存复杂图元：把绘制成本高的背景、图标、组合图形预先画在离屏画布上，运行时一条 drawImage 贴上来——把一百条指令压缩成一次纹理拷贝；
  2. 脏矩形局部重绘：只重画发生变化的最小矩形区域（用 clearRect 加 drawImage 或 clip 限制范围），适合"整幅画面基本静止、局部在动"的场景；全屏都在动时不适用；
  3. 分层 canvas：把高频变化层与低频静态层拆成上下叠放的多块 canvas——背景图一次绘制常年不动，前景每帧重绘，两层互不牵连，这是图表库处理大数据量渲染的常用结构；
  4. 避免每帧创建对象、数组与闭包：每帧 new 出来的对象都会加剧 GC，GC 停顿在帧率上表现为周期性卡顿。球体、粒子应预分配、循环复用（本页压测组件的做法），帧内计算用 Float32Array 等定长结构而非临时数组。

还有一条同样重要：每帧不要触碰 Vue 响应式状态。在 frame 回调里改 ref 会让组件每帧重新渲染，渲染成本远超绘制本身；FPS 数字这类高频信息直接画进画布，才是正确的归属。

像素操作：getImageData 与 putImageData ​

js
// willReadFrequently：提示浏览器把后备存储放在 CPU 侧，频繁读写像素更快
const ctx = canvas.getContext('2d', { willReadFrequently: true })
const img = ctx.getImageData(0, 0, w, h) // 快照：Uint8ClampedArray，RGBA 四通道排布
const d = img.data
for (let i = 0; i < d.length; i += 4) {
  // 灰度：按人眼敏感度加权（绿色权重最大）
  const v = 0.299 * d[i] + 0.587 * d[i + 1] + 0.114 * d[i + 2]
  d[i] = d[i + 1] = d[i + 2] = v
  // 反色：255 减去原通道值，alpha（d[i+3]）保持不变
  // d[i] = 255 - d[i]; d[i+1] = 255 - d[i+1]; d[i+2] = 255 - d[i+2]
}
ctx.putImageData(img, 0, 0) // 原样写回位图

两个必须理解的特性：getImageData 返回的是那一刻的位图快照，之后画布再怎么变它都不同步；putImageData 是原始像素直写，绕过一切变换矩阵、样式与合成规则，setTransform 对它完全无效——这也是像素处理通常放在"逻辑尺寸等于位图尺寸"的源画布上进行的原因。

完整代码示例 ​

第一个演示是 1000 球上限的物理压场：等差档位切换球数，右上角实时显示按帧时间滑动平均算出的 FPS，可以暂停/继续，直观感受图元数量与帧率的关系。

右上角为实时帧率（帧时间滑动平均），数值因设备而异；逐档切换数量感受渲染压力。

试试：从 50 球逐档点到 1000 球，盯着右上角 FPS（数值因设备而异）看它掉到多少；中途按"暂停"，切到别的标签页再回来点"继续"，感受 dt 封顶为什么必不可少。

核心代码与组件逻辑一致，可直接复制复用：

vue
// 文件: docs/.vitepress/components/canvas/CanvasBalls.vue
<template>
  <div class="demo-card">
    <div class="stage">
      <canvas ref="canvasRef"></canvas>
    </div>
    <div class="control-row">
      <button
        v-for="n in counts"
        :key="n"
        class="ctrl-btn"
        :class="{ active: count === n }"
        v-text="String(n) + ' 球'"
        @click="setCount(n)"
      ></button>
      <button class="ctrl-btn" v-text="pauseText" @click="togglePause"></button>
      <p class="tip">右上角为实时帧率（帧时间滑动平均），数值因设备而异；逐档切换数量感受渲染压力。</p>
    </div>
  </div>
</template>
<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'
const counts = [50, 200, 500, 1000]
const MAX_BALLS = 1000
const PALETTE = ['#2f7ae5', '#f0a020', '#3fa96f', '#d9564f', '#8a63d2']
const canvasRef = ref(null)
const count = ref(200)
const pauseText = ref('暂停')
let ctx = null
let cssW = 0
let cssH = 0
let rafId = 0
let paused = false
let last = 0
// 预分配上限数量的球：切换数量只改可见范围，避免 GC 抖动
const balls = []
for (let i = 0; i < MAX_BALLS; i++) {
  balls.push({ x: 0, y: 0, vx: 0, vy: 0, r: 3 })
}
// 帧时间滑动平均：环形缓冲最近 30 帧，据此计算实时 FPS
const FT_N = 30
const ftBuf = new Float32Array(FT_N)
let ftIdx = 0
let ftCount = 0
let ftSum = 0
function pushFrameTime(ms) {
  if (ftCount < FT_N) {
    ftSum += ms
  } else {
    ftSum -= ftBuf[ftIdx] // 缓冲已满：先减去被覆盖的旧值
    ftSum += ms
  }
  ftBuf[ftIdx] = ms
  ftIdx = (ftIdx + 1) % FT_N
  ftCount = Math.min(ftCount + 1, FT_N)
}
function initBalls() {
  for (let i = 0; i < MAX_BALLS; i++) {
    const b = balls[i]
    b.x = Math.random() * cssW
    b.y = Math.random() * cssH
    const angle = Math.random() * Math.PI * 2
    const speed = 40 + Math.random() * 90
    b.vx = Math.cos(angle) * speed
    b.vy = Math.sin(angle) * speed
    b.r = 2 + Math.random() * 2.5
  }
}
// 物理推进：按 delta time 积分位置，撞墙时把对应速度分量取反
function update(dt) {
  const n = count.value
  for (let i = 0; i < n; i++) {
    const b = balls[i]
    b.x += b.vx * dt
    b.y += b.vy * dt
    if (b.x < b.r) {
      b.x = b.r
      b.vx = Math.abs(b.vx)
    } else if (b.x > cssW - b.r) {
      b.x = cssW - b.r
      b.vx = -Math.abs(b.vx)
    }
    if (b.y < b.r) {
      b.y = b.r
      b.vy = Math.abs(b.vy)
    } else if (b.y > cssH - b.r) {
      b.y = cssH - b.r
      b.vy = -Math.abs(b.vy)
    }
  }
}
function draw() {
  ctx.fillStyle = '#ffffff'
  ctx.fillRect(0, 0, cssW, cssH)
  const n = count.value
  for (let i = 0; i < n; i++) {
    const b = balls[i]
    ctx.fillStyle = PALETTE[i % PALETTE.length]
    ctx.beginPath()
    ctx.arc(b.x, b.y, b.r, 0, Math.PI * 2)
    ctx.fill()
  }
  // FPS 文本直接画进画布：避免每帧改 Vue 响应式状态触发组件重渲染
  const fps = ftCount > 0 ? 1000 / (ftSum / ftCount) : 0
  ctx.font = '12px sans-serif'
  ctx.textAlign = 'right'
  ctx.textBaseline = 'top'
  ctx.fillStyle = '#1f2937'
  ctx.fillText('FPS ' + fps.toFixed(0) + ' · ' + n + ' 球', cssW - 10, 8)
}
function frame(now) {
  const raw = now - last
  last = now
  pushFrameTime(raw)
  update(Math.min(raw, 33) / 1000) // dt 封顶，防切页回来跳变
  draw()
  rafId = requestAnimationFrame(frame)
}
function setCount(n) {
  count.value = n
}
function togglePause() {
  paused = !paused
  pauseText.value = paused ? '继续' : '暂停'
  if (paused) {
    cancelAnimationFrame(rafId) // 暂停即彻底停帧，而不是空转
  } else {
    last = performance.now() // 重置时间基准，防止累计出巨大 dt
    rafId = requestAnimationFrame(frame)
  }
}
// 高清三步法：位图尺寸乘 DPR、setTransform 缩放坐标系、CSS 尺寸交给样式表
function setupCanvas() {
  const cv = canvasRef.value
  const dpr = window.devicePixelRatio || 1
  cssW = cv.clientWidth
  cssH = cv.clientHeight
  cv.width = Math.round(cssW * dpr)
  cv.height = Math.round(cssH * dpr)
  ctx = cv.getContext('2d')
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0)
  // 尺寸变小后把越界的球夹回画布内
  for (let i = 0; i < MAX_BALLS; i++) {
    const b = balls[i]
    b.x = Math.min(b.x, cssW - b.r)
    b.y = Math.min(b.y, cssH - b.r)
  }
}
function onResize() {
  setupCanvas()
}
onMounted(() => {
  setupCanvas()
  initBalls()
  window.addEventListener('resize', onResize)
  last = performance.now()
  rafId = requestAnimationFrame(frame)
})
onBeforeUnmount(() => {
  cancelAnimationFrame(rafId)
  window.removeEventListener('resize', onResize)
})
</script>

第二个演示是逐像素滤镜：先程序化生成一张 480x300 的源图案，"灰度"与"反色"按钮用 ImageData 在源位图上完成运算，显示画布只负责高清呈现。

当前处理：原图；像素运算在 480x300 的源位图上完成，与显示尺寸和 DPR 无关

试试：三个按钮来回切换，观察灰度图里白色圆比深色圆亮得多——这正是 0.299、0.587、0.114 三个权重对绿红蓝通道敏感度的表达。

核心代码与组件逻辑一致，可直接复制复用：

vue
// 文件: docs/.vitepress/components/canvas/CanvasPixels.vue
<template>
  <div class="demo-card">
    <div class="stage">
      <canvas ref="canvasRef"></canvas>
    </div>
    <div class="control-row">
      <button
        v-for="f in filters"
        :key="f.key"
        class="ctrl-btn"
        :class="{ active: filter === f.key }"
        v-text="f.label"
        @click="applyFilter(f.key)"
      ></button>
      <p class="tip">当前处理：<span v-text="filterLabel"></span>；像素运算在 480x300 的源位图上完成，与显示尺寸和 DPR 无关</p>
    </div>
  </div>
</template>
<script setup>
import { ref, computed, onMounted, onBeforeUnmount } from 'vue'
const IMG_W = 480
const IMG_H = 300
const filters = [
  { key: 'origin', label: '原图' },
  { key: 'gray', label: '灰度' },
  { key: 'invert', label: '反色' },
]
const filter = ref('origin')
const filterLabel = computed(() => filters.find((f) => f.key === filter.value).label)
const canvasRef = ref(null)
let ctx = null          // 显示画布上下文：只负责高清呈现
let off = null          // 离屏源画布：像素处理的真正战场
let octx = null         // 离屏画布上下文
let originalData = null // 首次缓存的原始像素快照
let workData = null     // 复用的处理缓冲，避免每次点击都重新分配内存
// 程序化生成源图案：渐变背景 + 半透明几何 + 斜纹 + 水印
function buildSource() {
  off = document.createElement('canvas')
  off.width = IMG_W
  off.height = IMG_H
  // willReadFrequently：提示浏览器把后备存储放在 CPU 侧，频繁读写像素更快
  octx = off.getContext('2d', { willReadFrequently: true })
  const g = octx.createLinearGradient(0, 0, IMG_W, IMG_H)
  g.addColorStop(0, '#2f7ae5')
  g.addColorStop(0.5, '#7a5fd0')
  g.addColorStop(1, '#e58a3f')
  octx.fillStyle = g
  octx.fillRect(0, 0, IMG_W, IMG_H)
  octx.globalAlpha = 0.35
  octx.fillStyle = '#ffffff'
  octx.beginPath()
  octx.arc(120, 90, 70, 0, Math.PI * 2)
  octx.fill()
  octx.fillStyle = '#111827'
  octx.beginPath()
  octx.arc(330, 210, 92, 0, Math.PI * 2)
  octx.fill()
  octx.globalAlpha = 1
  octx.strokeStyle = 'rgba(255, 255, 255, 0.25)'
  octx.lineWidth = 6
  for (let x = -IMG_H; x < IMG_W; x += 36) {
    octx.beginPath()
    octx.moveTo(x, 0)
    octx.lineTo(x + IMG_H, IMG_H)
    octx.stroke()
  }
  octx.font = 'bold 26px sans-serif'
  octx.fillStyle = 'rgba(255, 255, 255, 0.85)'
  octx.fillText('离屏图案 480x300', 22, 48)
  // 一次性读取全部像素并缓存；后续所有处理都从这份数据出发
  originalData = octx.getImageData(0, 0, IMG_W, IMG_H)
  workData = octx.createImageData(IMG_W, IMG_H)
}
// 灰度按 0.299R + 0.587G + 0.114B 加权（人眼对绿色最敏感），反色取 255 减原值
function applyFilter(kind) {
  filter.value = kind
  if (!originalData) return
  workData.data.set(originalData.data) // 整体复制原始像素，保证可以来回切换
  const d = workData.data
  if (kind === 'gray') {
    for (let i = 0; i < d.length; i += 4) {
      const v = 0.299 * d[i] + 0.587 * d[i + 1] + 0.114 * d[i + 2]
      d[i] = v
      d[i + 1] = v
      d[i + 2] = v
    }
  } else if (kind === 'invert') {
    for (let i = 0; i < d.length; i += 4) {
      d[i] = 255 - d[i]
      d[i + 1] = 255 - d[i + 1]
      d[i + 2] = 255 - d[i + 2]
    }
  }
  // putImageData 直写源位图（不受 setTransform 影响），显示画布只用 drawImage 呈现
  octx.putImageData(workData, 0, 0)
  blit()
}
// 把离屏源图等比缩放、居中绘制到显示画布，避免拉伸变形
function blit() {
  if (!ctx) return
  ctx.fillStyle = '#ffffff'
  ctx.fillRect(0, 0, cssW, cssH)
  const s = Math.min(cssW / IMG_W, cssH / IMG_H)
  const w = IMG_W * s
  const h = IMG_H * s
  const dx = (cssW - w) / 2
  const dy = (cssH - h) / 2
  ctx.drawImage(off, dx, dy, w, h)
  ctx.strokeStyle = '#d3d9e3'
  ctx.lineWidth = 1
  ctx.strokeRect(dx + 0.5, dy + 0.5, w, h)
}
// 高清三步法：位图尺寸乘 DPR、setTransform 缩放坐标系、CSS 尺寸交给样式表
function setupCanvas() {
  const cv = canvasRef.value
  const dpr = window.devicePixelRatio || 1
  cssW = cv.clientWidth
  cssH = cv.clientHeight
  cv.width = Math.round(cssW * dpr)
  cv.height = Math.round(cssH * dpr)
  ctx = cv.getContext('2d')
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0)
  blit()
}
function onResize() {
  setupCanvas()
}
onMounted(() => {
  buildSource()
  setupCanvas()
  window.addEventListener('resize', onResize)
})
onBeforeUnmount(() => {
  window.removeEventListener('resize', onResize)
})
</script>

最佳实践与常见坑 ​

  • 运动逻辑必须乘 delta time：以"每帧加固定值"写动画，页面在 60Hz 与 120Hz 屏幕上的速度会差一倍；以时间为基准才能让动画在任何设备上节奏一致，dt 还要封顶，否则切页回来第一帧物体会瞬移穿墙；
  • 卸载时 cancelAnimationFrame 与 removeEventListener 缺一不可：rAF 回调持有整个组件闭包，只 cancel 不移除 resize 监听，组件销毁后回调仍会触发并访问已卸载的 DOM；反过来只移除监听不 cancel，帧循环在后台永远掉电；
  • 高频状态画进画布，不要进 Vue：每帧更新 ref 会触发组件重渲染，成本比 Canvas 绘制本身高一个量级；FPS、倒计时、坐标读数这类每帧变化的信息，正确的家在画布上；
  • getImageData 是昂贵的同步读操作：它要把 GPU（或加速层）里的位图搬回 CPU 内存，大画布上一次调用可达数毫秒；读一次缓存起来反复用，并在创建上下文时声明 willReadFrequently: true；
  • putImageData 绕过所有变换：它不认 setTransform、不认 DPR 缩放，直接按位图坐标写像素；想在 DPR 画布上呈现像素处理结果，正确姿势是处理发生在源位图、显示走 drawImage（本页滤镜组件的结构）；
  • 暂停要停帧而不是跳过绘制：用布尔标记让 frame 回调"空转"仍然占用 rAF 配额；直接 cancelAnimationFrame，恢复时重置 last 再重启，CPU 才真正归零；
  • 预分配代替运行期创建：1000 个球如果每帧 new 一次，GC 会在帧率曲线上打出周期性锯齿；上限预分配加"只改可见数量"的模式，是这个量级动画的标准写法。

小结 ​

要点回顾：动画是快速重绘的错觉，rAF 把循环对齐到显示器刷新并在页面隐藏时自动暂停；标准帧循环 = delta time 推进状态加重绘，dt 必须封顶；物理运动就是积分与反弹；性能四板斧（离屏缓存、脏矩形、分层 canvas、避免每帧分配）各有适用面，共同底线是别让 Vue 介入帧循环；像素操作在 ImageData 上进行，灰度与反色只是两行加权公式，工程要点在于源位图与显示画布分离。
