5.2 常用图表与配置体系 ​

上一页建立了"坐标系 + 系列 + 辅助组件"的三层模型，本页横向铺开常用 series 类型，再讲清配置体系的三个进阶杠杆：dataset 数据驱动、多 grid 布局、visualMap 视觉映射，最后用实例联动把多个图表粘合成一张小屏。

概念解析 ​

ECharts 的配置体系是一套"类型系统"：series.type 决定图元形态，dataset 与 encode 决定数据如何流动，visualMap 决定第三维如何编码进视觉通道，多 grid 让一个实例承载多个坐标系。理解这套体系后，绝大多数图表需求都能翻译成配置，而不是代码。

为什么值得专门学配置体系：同样是画散点图，逐系列手写 data 和用 dataset + encode 的维护成本差距巨大；同样是多图联动，各自为政的实例和 connect 分组的管理成本也不在一个量级。配置体系是 ECharts 从"能画图"到"能做产品"的分界线。

典型应用场景：数据大屏（多图联动、共享数据源）、多维数据探索（散点编码第三维）、统计报表（堆叠、百分比构成）。选型的横向对比见核心特性对比。

核心 API 与原理 ​

series 类型速览 ​

类型一句话用途
bar类目间数值比较，直角坐标系柱形
line时间序列与趋势，支持平滑、面积、堆叠
pie构成占比，适合类目少、维度少的场景
scatter二维分布与相关性，可再编码第三维
effectScatter带涟漪特效的散点，常用于突出重点点或地图标点
heatmap密度热度矩阵，x 与 y 交叉处用颜色深浅表达数值
boxplot统计分布：中位数、四分位距、离群点
graph关系网络：节点加边，支持力导向等布局

选择口诀：比大小用 bar，看趋势用 line，看占比用 pie，找相关性用 scatter，看分布用 boxplot，看关系用 graph。饼图类目超过七八个就该换 bar 了——扇区一多占比根本读不出来。

dataset + encode：数据驱动的配置 ​

传统写法里每个 series 手写一份 data，数据一换要改多处。dataset 把数据抽到 option 顶层，series 用 encode 声明"维度怎么映射到视觉通道"：

js
{
  dataset: {
    // dimensions 显式声明列名，避免依赖源数据首行推断
    dimensions: ['月份', '销量', '增速'],
    source: [
      ['1月', 820, 2.1],
      ['2月', 932, 4.6],
      ['3月', 901, 3.8]
      // …
    ]
  },
  xAxis: { type: 'category' },
  yAxis: { type: 'value' },
  series: [
    { type: 'bar', encode: { x: '月份', y: '销量' } },
    { type: 'line', encode: { x: '月份', y: '增速' } }
  ]
}

三个收益：一份 source 被多个系列共享，换数据只改一处；encode 可以用维度名或维度索引，语义清晰；encode 能映射的不止 x 与 y，还有 size、tooltip、itemName 等，配合下一页的 visualMap 可以把第三维、第四维都编码进去。数据加工（排序、过滤、聚合）还可以交给 dataset.transform 在配置层完成，这里一句带过，用到时查官方 transform 文档即可。

多 grid：一个实例画多张图 ​

grid、xAxis、yAxis 都接受数组，用 gridIndex 声明坐标轴属于哪个 grid，series 再用 xAxisIndex、yAxisIndex 指向哪套轴。一个实例即可上下布局两张图：

js
{
  grid: [
    { top: '8%', height: '36%' },    // 第 0 个 grid：上半区
    { bottom: '8%', height: '36%' }  // 第 1 个 grid：下半区
  ],
  xAxis: [
    { gridIndex: 0, type: 'category', data: months },
    { gridIndex: 1, type: 'category', data: months }
  ],
  yAxis: [{ gridIndex: 0 }, { gridIndex: 1 }],
  series: [
    { type: 'bar', xAxisIndex: 0, yAxisIndex: 0, data: sales },
    { type: 'line', xAxisIndex: 1, yAxisIndex: 1, data: profit }
  ]
}

何时用多 grid 而不是多个实例：同源数据的多视图（如上柱下线）、需要共享一份主题配置或统一导出截图时，多 grid 更省心；但所有图只能画在同一张画布内，尺寸联动靠百分比布局。

stack 堆叠与百分比堆叠 ​

同名 stack 的系列会纵向累加，这是观察构成变化的标准写法：

js
series: [
  { name: '线上', type: 'bar', stack: 'total', data: online },
  { name: '线下', type: 'bar', stack: 'total', data: offline }
]

需要"百分比堆叠"时，注意 ECharts 没有原生的归一化开关（以 6.x 为准），惯用做法是先把数据换算成占比再普通堆叠：

js
// 每个类目下各系列值除以该类目总和，换算成百分比后再 stack
function toPercent(rows) {
  return rows.map((row) => {
    const sum = row.values.reduce((a, b) => a + b, 0)
    return { name: row.name, type: 'bar', stack: 'total',
      data: row.values.map((v) => +((v / sum) * 100).toFixed(2)) }
  })
}

tooltip 里若还要展示原始值与占比，用 formatter 回调从闭包里取原始数据拼接即可。

visualMap：把第三维编码到视觉通道 ​

visualMap 把某个数据维度的取值映射为视觉通道：颜色、符号大小、符号形状等。分两种：

  • 连续型（continuous）：值域到渐变色带，配合 calculable 可拖拽过滤，适合探索"数值越大颜色越暖"这类连续关系；
  • 分段型（piecewise）：把值域切成离散区间，图例直接显示为若干色块，适合分级（如"低、中、高风险"）。

散点图编码第三维是最典型的用法：dimension 指定用第几维，inRange 声明映射目标，seriesIndex 限定作用于哪些系列。下文的示例组件中，散点的颜色与大小就都由第 2 维"强度"驱动。

实例联动 connect ​

多个图表实例设置同一个 group 后注册进连接池，tooltip、legend、dataZoom 的交互就会在组内自动同步：

js
chartA.group = 'dashboard'
chartB.group = 'dashboard'
echarts.connect('dashboard')          // 组内所有实例双向联动
// echarts.connect([chartA, chartB])  // 等价写法：直接传实例数组
// echarts.disconnect('dashboard')    // 取消联动

联动是双向广播：在任一实例上切换图例、拖动 dataZoom、触发 tooltip，组内其他实例同步响应。联动按"名字"匹配系列，两图系列名一致时图例联动最直观。

完整代码示例 ​

试试：点击任意一侧的图例"分组 B"，两侧的系列同时隐藏或显示——这就是 connect 联动；在左图底部拖动 visualMap 滑块，按强度过滤散点；再点"随机数据"按钮，两图数据同步刷新，但配置原样保留。

组件核心代码如下（左图 dataset + encode + visualMap，右图聚合饼图，互相联动）：

vue
// 文件: docs/.vitepress/components/echarts/EchartsDataset.vue
<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'

const scatterEl = ref(null)
const pieEl = ref(null)
let scatterChart = null
let pieChart = null

// 散点系列与饼图扇区共用一组名字，联动后图例开关可跨图同步
const groupNames = ['分组 A', '分组 B', '分组 C']

// 生成 60 行明细 [x, y, 强度]，x 按分组错开区间，分到三份 dataset 源数据
function genData() {
  const sources = [[], [], []]
  for (let i = 0; i < 60; i++) {
    const g = Math.floor(Math.random() * 3)
    sources[g].push([
      Math.round(g * 34 + Math.random() * 34),
      Math.round(Math.random() * 100),
      Math.round(Math.random() * 100)
    ])
  }
  return sources
}

function buildScatterOption(sources) {
  return {
    legend: { top: 0, data: groupNames },
    tooltip: {
      trigger: 'item',
      // dataset 模式下 params.value 即源数据的一整行
      formatter: (p) => `x: ${p.value[0]}，y: ${p.value[1]}，强度: ${p.value[2]}`
    },
    grid: { left: 44, right: 24, top: 36, bottom: 78 },
    xAxis: { type: 'value', min: 0, max: 102, name: 'X' },
    yAxis: { type: 'value', min: 0, max: 102, name: 'Y' },
    dataset: sources.map((src) => ({ source: src })),
    series: groupNames.map((name, i) => ({
      name,
      type: 'scatter',
      datasetIndex: i,
      encode: { x: 0, y: 1 } // 维度索引映射：x 取第 0 维，y 取第 1 维
    })),
    // 连续型 visualMap：第 2 维同时编码颜色渐变与符号大小
    visualMap: {
      type: 'continuous',
      dimension: 2,
      seriesIndex: [0, 1, 2], // 显式限定作用系列
      min: 0,
      max: 100,
      calculable: true,
      left: 'center',
      bottom: 0,
      text: ['强', '弱'],
      inRange: { color: ['#5470c6', '#91cc75', '#ee6666'], symbolSize: [8, 26] }
    }
  }
}

// 坑点：饼图无法直接 encode 逐行明细——60 行 source 会拆出 60 个扇区，
// 聚合类图表必须先把明细算成结果（这里取各分组的行数）
function buildPieOption(sources) {
  return {
    legend: { top: 0, data: groupNames },
    tooltip: { trigger: 'item', formatter: '{b}: {c} 个（{d}%）' },
    series: [{
      type: 'pie',
      radius: '60%',
      center: ['50%', '58%'],
      label: { formatter: '{b}\n{d}%' },
      data: sources.map((src, i) => ({ name: groupNames[i], value: src.length }))
    }]
  }
}

function refresh() {
  const sources = genData()
  // 增量 setOption：散点只更新 dataset 源数据，饼图只更新聚合结果
  scatterChart.setOption({ dataset: sources.map((src) => ({ source: src })) })
  pieChart.setOption({
    series: [{ data: sources.map((src, i) => ({ name: groupNames[i], value: src.length })) }]
  })
}

function handleResize() {
  if (scatterChart) scatterChart.resize()
  if (pieChart) pieChart.resize()
}

onMounted(async () => {
  const echarts = await import('echarts') // SSR 安全：动态引入
  scatterChart = echarts.init(scatterEl.value, null, { renderer: 'canvas' })
  pieChart = echarts.init(pieEl.value, null, { renderer: 'canvas' })
  const sources = genData()
  scatterChart.setOption(buildScatterOption(sources))
  pieChart.setOption(buildPieOption(sources))
  // 实例联动：同 group + 全局 connect，tooltip/legend/dataZoom 组内双向同步
  scatterChart.group = 'dataset-demo'
  pieChart.group = 'dataset-demo'
  echarts.connect('dataset-demo')
  window.addEventListener('resize', handleResize)
})

onBeforeUnmount(() => {
  window.removeEventListener('resize', handleResize)
  if (scatterChart) {
    scatterChart.dispose()
    scatterChart = null
  }
  if (pieChart) {
    pieChart.dispose()
    pieChart = null
  }
})
</script>

<template>
  <div class="demo-card">
    <div class="controls">
      <button @click="refresh">随机数据</button>
    </div>
    <div class="charts">
      <div ref="scatterEl" class="chart"></div>
      <div ref="pieEl" class="chart"></div>
    </div>
  </div>
</template>

最佳实践与常见坑 ​

  1. dataset 源数据建议显式声明 dimensions。 二维数组形式时 ECharts 会把首行推断为列名，对象数组时按字段顺序推断，源数据格式一变映射就全乱。显式 dimensions 后，数据行序、字段增删都不影响 encode。
  2. 饼图不能直接吃逐行明细。 dataset 对 pie 这类"一行一个图元"的图表是直接按行映射的，60 行明细会变成 60 个扇区。聚合类图表（pie、部分 bar）要先把明细算成聚合结果再喂给 series.data 或 dataset。
  3. 多 grid 时 gridIndex、xAxisIndex 忘配是高发错误。 所有系列默认落到第 0 套坐标系上，表现是"两张图挤在一张图的位置"。配置多套轴后逐系列核对索引。
  4. visualMap 不限定 seriesIndex 会误伤其他系列。 visualMap 默认作用于 option 内所有系列，散点加饼图共存时饼图颜色会被映射逻辑改写。养成写 seriesIndex 的习惯。
  5. stack 只对同类系列有意义。 bar 和 line 设同名 stack 的行为难以解释，且含负数数据时堆叠方向可能不符合直觉，先在小数据集上验证再上生产。
  6. connect 前确认实例存活、group 一致。 对已 dispose 的实例做联动注册会产生幽灵引用；组内实例过多时 tooltip 同步也有开销，一张屏联动 3 到 4 个实例是舒适上限。

小结 ​

本页速览了八类常用 series 的适用边界，掌握了 dataset + encode 数据驱动、多 grid 单实例多图、stack 堆叠与百分比归一化、visualMap 视觉映射和 connect 实例联动五件配置武器。下一篇交互、主题与性能优化深入 tooltip、dataZoom 与事件系统，并给出渲染器选型与大数据量渲染的实测方法。
