3.3 SVG 动画与交互 ​

SVG 节点是普通 DOM，CSS 动画、JS 动画、DOM 事件三件套全部天然可用——这是保留模式相对 Canvas 的最大红利。本页梳理 SVG 动画的三条路线与各自的坑，讲透描边动画的原理与事件命中规则，并用圆形进度环、正弦波两个演示落地。

概念解析 ​

SVG 动画的三条路线 ​

让 SVG 动起来，本质是让节点的属性随时间变化，驱动方式有三类：CSS 动画（transition 与 keyframes 直接作用于表现属性，声明式、成本最低）；SMIL（用 animate 等标签写在 XML 里）；JS 驱动（rAF 逐帧改属性，或 Web Animations API）。三条路线可以混用，但同一属性同一时刻只应有一个驱动者。

交互为何是 SVG 的主场 ​

三种方式画柱状图已经展示过：SVG 图形的 hover、点击是浏览器免费赠送的——每个节点都在事件系统里，命中检测由浏览器完成。Canvas 要实现同样的交互，得自己维护图形列表、手写坐标检测或离屏色键。节点规模不大、交互密集的场景，SVG 的开发效率优势是压倒性的。

典型应用场景 ​

  • 加载与进度指示：旋转 spinner、进度环、骨架屏呼吸效果；
  • 描边动画：签名书写、图标勾勒、路径高亮引导；
  • 数据图表的微交互：hover 高亮、提示框跟随、选中态切换；
  • 小规模动态图形：正弦波、仪表指针、流程图流动效果。

核心 API 与原理 ​

CSS 动画作用于 SVG ​

fill、stroke、opacity、stroke-dashoffset 等表现属性都能被 transition 与 keyframes 插值。最大的坑在 transform：SVG 元素的变换参照默认是整个 viewBox 坐标系，rotate(45deg) 绕的是原点 (0,0) 而不是图形自身中心——一个小小的旋转动画会让图形绕着画面左上角"飞出去"。解法是两行 CSS：

css
.spin {
  transform-box: fill-box; /* 变换参照改为元素自身包围盒 */
  transform-origin: center; /* 绕包围盒中心旋转 */
  animation: rot 2s linear infinite;
}
@keyframes rot {
  to { transform: rotate(360deg); }
}

transform-box 的默认值是 view-box，改成 fill-box 后 transform-origin 的百分比与 center 才按图形自身计算。这是 SVG 旋转动画的第一必修课。

SMIL：仍可用，但不推荐 ​

SMIL 用标签描述动画，例如让圆的水平坐标在 2 秒内从 20 变到 200 可以写成在 circle 里嵌一个 animate 标签并设置 attributeName、from、to、dur。它至今仍在浏览器里工作，但规范早已停止演进，Chrome 一度计划移除；新项目请直接用 CSS 或 JS，了解它只是为了读懂旧代码。

JS 驱动的两种方式 ​

rAF 逐帧改属性最灵活：每帧读时间、算数值、写属性，物理运动、拖拽跟随、连续波形都靠它。代价是每帧一次主线程计算，且要自己管理取消：

js
let rafId = 0
function tick(now) {
  const t = (now - start) / 1000
  circle.setAttribute('cx', 100 + 80 * Math.sin(t)) // 每帧写一个属性
  rafId = requestAnimationFrame(tick)
}
rafId = requestAnimationFrame(tick)
// 组件卸载或动画结束时务必 cancelAnimationFrame(rafId)

Web Animations API 则是声明式的 JS 动画：语法接近 CSS keyframes，但可以在运行时创建、暂停、倒放，且合成器友好的属性（transform、opacity）不阻塞主线程：

js
const anim = el.animate(
  [{ transform: 'rotate(0deg)' }, { transform: 'rotate(360deg)' }],
  { duration: 2000, iterations: Infinity }
)
anim.pause() // 随时控制播放状态

经验法则：简单状态过渡用 CSS transition；时间轴复杂、需要控制播放的用 WAAPI；数值依赖实时输入（指针位置、物理模拟）的用 rAF。

描边动画原理 ​

"路径自己画出来"的效果只用两个属性：stroke-dasharray 设为路径总长度（虚线变成一段与路径等长的实线），stroke-dashoffset 从总长度渐变到 0（实线段从完全藏起到完全展开）。总长用上一页的 getTotalLength() 量取：

css
.draw-path {
  stroke-dasharray: 500;    /* 等于 getTotalLength() 的量取结果 */
  stroke-dashoffset: 500;   /* 初始完全隐藏 */
  animation: draw 1.5s ease forwards;
}
@keyframes draw {
  to { stroke-dashoffset: 0; } /* 偏移归零，路径"画"完 */
}

本页第一个演示的进度环用的正是这个原理，只是 dashoffset 不再走 keyframes，而是由进度值实时计算。

事件模型与命中规则 ​

SVG 节点支持全部普通 DOM 事件：click、pointerenter、pointerdown……但命中检测有自己的规则，由 pointer-events 属性控制，默认值 visiblePainted 的含义是"指针必须落在实际被绘制的像素上"：

  • fill="none" 的图形，内部区域点击不触发事件——只有描边线上能点中；想让空心图形整个可点，把 fill 改成 transparent（透明色也算被绘制），或设 pointer-events="all"；
  • 反过来，想让某个遮罩层完全不挡事件，设 pointer-events="none"；
  • 其他常用值：visibleFill（只认填充区）、visibleStroke（只认描边）、painted（认绘制区，不管可见性）。

与 Canvas 的交互成本对比 ​

SVG 的每个图形都是事件系统的一等公民，hover 一个圆点只需监听 pointerenter；Canvas 里同样的事要自己记录每个圆的位置与半径，在 pointermove 里逐个做距离检测，图形上千后还得上空间索引。但账有两面：SVG 节点多了之后，DOM 管理与样式重算的成本会反超 Canvas 的位图绘制——交互密集、节点有限选 SVG，渲染密集、节点海量选 Canvas，这条分界线在性能对比一章还有量化展开。

完整代码示例 ​

第一个演示是圆形进度环：滑块设定目标进度，圆环通过 dashoffset 的 CSS transition 平滑跟随；点击"播放动画"则由 rAF 驱动，从 0 缓动增长到目标值，中心实时显示百分比。

试试：先拖动滑块观察 transition 的平滑跟随；再把目标设为 85，点"播放动画"，注意 rAF 播放期间 transition 被临时关闭，避免两套驱动在同一属性上打架。

核心代码与组件逻辑一致，可直接复制复用：

vue
// 文件: docs/.vitepress/components/svg/SvgRing.vue
<template>
  <div class="demo-card">
    <div class="stage">
      <svg viewBox="0 0 200 200" class="ring-svg" role="img" aria-label="圆形进度环">
        <!-- 底环：完整圆周的浅色轨道 -->
        <circle cx="100" cy="100" r="80" class="ring-track" />
        <!--
          进度环：dasharray 取整周长，dashoffset 越大露出的弧越短；
          rotate(-90) 让弧的起点从正右方转到正上方
        -->
        <circle
          cx="100"
          cy="100"
          r="80"
          class="ring-value"
          :class="{ playing }"
          :stroke-dasharray="C"
          :stroke-dashoffset="dashOffset"
          transform="rotate(-90 100 100)"
        />
        <text x="100" y="96" text-anchor="middle" class="ring-num" v-text="display + '%'"></text>
        <text x="100" y="122" text-anchor="middle" class="ring-label">完成进度</text>
      </svg>
    </div>
    <div class="control-row">
      <label class="ctrl-item">
        <span class="ctrl-name">目标进度</span>
        <input type="range" min="0" max="100" step="1" v-model.number="display" :disabled="playing" />
        <span class="ctrl-val" v-text="display"></span>
      </label>
      <button class="ctrl-btn" :disabled="playing" @click="play">播放动画</button>
    </div>
  </div>
</template>

<script setup>
import { ref, computed, onBeforeUnmount } from 'vue'

const R = 80
// 整周长：进度环 dasharray 的基准，保留两位小数即可
const C = Math.round(2 * Math.PI * R * 100) / 100
const display = ref(60) // 当前渲染的百分比，初值固定
const playing = ref(false)
let rafId = 0

// dashoffset 从周长到 0 即"从无到有"画出整圆
const dashOffset = computed(() => Math.round(C * (1 - display.value / 100) * 100) / 100)

// rAF 驱动：从 0 缓动增长到当前滑块目标值，期间关闭 CSS transition 避免逐帧插值打架
function play() {
  cancelAnimationFrame(rafId)
  const to = display.value
  const dur = 1200
  const t0 = performance.now()
  playing.value = true
  display.value = 0
  const tick = (now) => {
    const k = Math.min(1, (now - t0) / dur)
    const eased = 1 - Math.pow(1 - k, 3) // easeOutCubic 缓动：先快后慢
    display.value = Math.round(to * eased)
    if (k < 1) {
      rafId = requestAnimationFrame(tick)
    } else {
      playing.value = false
    }
  }
  rafId = requestAnimationFrame(tick)
}

onBeforeUnmount(() => {
  cancelAnimationFrame(rafId) // 组件卸载时取消未完成的动画帧
})
</script>

.ring-value {
  fill: none; stroke: var(--vp-c-brand-1); stroke-width: 14; stroke-linecap: round;
  transition: stroke-dashoffset 0.3s ease; /* 滑块拖动时平滑过渡 */
}
.ring-value.playing { transition: none; } /* rAF 逐帧驱动时关掉 transition */
.ring-num { fill: var(--vp-c-text-1); font-size: 30px; font-weight: 600; }
.ring-label { fill: var(--vp-c-text-2); font-size: 13px; }
</style>

第二个演示是 rAF 驱动的正弦波：每帧重算 65 个采样点并替换 path 的 d 字符串，波上叠着 8 个数据点，hover 任意圆点会放大高亮并显示相对中线的偏移值——全程没有写一行命中检测代码。

hover 圆点查看数值；动画由 rAF 每帧重算 d 字符串驱动

成本提示：本演示每帧重算 65 个采样点并拼接 d 字符串，连同 8 个圆点共 9 个节点的属性更新，主线程轻松承担； 当节点规模上千、路径采样数百时，每帧的字符串拼接与属性解析会成为负担，应改用 Canvas 或降低更新频率。

试试：hover 不同位置的圆点，感受 DOM 事件的天然命中；点"暂停"再"继续"，波形从原地平滑续播而非跳变。

核心代码与组件逻辑一致，可直接复制复用：

vue
// 文件: docs/.vitepress/components/svg/SvgWave.vue
<template>
  <div class="demo-card">
    <div class="stage">
      <svg viewBox="0 0 640 300" class="stage-svg" role="img" aria-label="正弦波动画">
        <!-- 中线参考：帮助观察波形相对平衡位置的偏移 -->
        <line x1="0" y1="150" x2="640" y2="150" class="mid-line" />
        <!-- 正弦波路径：d 每帧由 rAF 重算 -->
        <path :d="waveD" class="wave" />
        <!-- 8 个数据点：DOM 事件天然命中，hover 高亮并显示数值 -->
        <g v-for="(p, i) in points" :key="i">
          <circle
            :cx="p.x"
            :cy="p.y"
            :r="hoverIndex === i ? 9 : 6"
            class="dot"
            :class="{ hot: hoverIndex === i }"
            @pointerenter="hoverIndex = i"
            @pointerleave="hoverIndex = -1"
          />
          <text
            v-if="hoverIndex === i"
            :x="p.x"
            :y="p.y - 16"
            text-anchor="middle"
            class="dot-label"
            v-text="formatValue(p.y)"
          ></text>
        </g>
      </svg>
    </div>
    <div class="control-row">
      <button class="ctrl-btn" v-text="running ? '暂停' : '继续'" @click="toggle"></button>
    </div>
  </div>
</template>

<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'

const W = 640
const MID_Y = 150
const AMP = 70 // 振幅
const SAMPLES = 65 // 每帧采样点数
const DOT_COUNT = 8

// 由相位计算正弦波路径的 d 字符串：纯函数、确定性，SSR 与客户端结果一致
function buildPath(phase) {
  const parts = []
  for (let i = 0; i < SAMPLES; i++) {
    const x = (i / (SAMPLES - 1)) * W
    const y = MID_Y + AMP * Math.sin((x / W) * Math.PI * 4 + phase)
    parts.push(`${i === 0 ? 'M' : 'L'} ${Math.round(x)} ${Math.round(y)}`)
  }
  return parts.join(' ')
}
// 8 个等距数据点，纵坐标落在同一正弦波上
function buildPoints(phase) {
  const arr = []
  for (let i = 0; i < DOT_COUNT; i++) {
    const x = 40 + (i * (W - 80)) / (DOT_COUNT - 1)
    const y = MID_Y + AMP * Math.sin((x / W) * Math.PI * 4 + phase)
    arr.push({ x: Math.round(x), y: Math.round(y) })
  }
  return arr
}

// 相位 0 的静态初值：挂载后才启动动画，保证 SSR 水合一致
const waveD = ref(buildPath(0))
const points = ref(buildPoints(0))
const hoverIndex = ref(-1)
const running = ref(false)

let rafId = 0
let phase = 0
let last = 0
function frame(now) {
  const dt = Math.min(50, now - last) // 帧间隔毫秒数，切后台回来时限制步长
  last = now
  phase += dt * 0.0022 // 相位推进速度
  waveD.value = buildPath(phase)
  points.value = buildPoints(phase)
  rafId = requestAnimationFrame(frame)
}
function start() {
  cancelAnimationFrame(rafId)
  running.value = true
  last = performance.now()
  rafId = requestAnimationFrame(frame)
}
function stop() {
  cancelAnimationFrame(rafId)
  running.value = false
}
function toggle() {
  if (running.value) {
    stop()
  } else {
    start()
  }
}
// 数据点数值：相对中线的偏移量，正数在上方
function formatValue(y) {
  const v = MID_Y - y
  return (v >= 0 ? '+' : '') + v
}

onMounted(start)
onBeforeUnmount(() => {
  cancelAnimationFrame(rafId) // 组件卸载时取消动画帧，VitePress 切页后不再空跑
})
</script>

最佳实践与常见坑 ​

  • 旋转动画先查 transform-box：SVG 元素默认绕 viewBox 原点旋转，不设 transform-box: fill-box 配 transform-origin: center，图形会绕着莫名其妙的位置打转；这条坑在 spinner、指针类动画里几乎必踩；
  • 一个属性只许一个驱动者：CSS transition 与 rAF 同时改 stroke-dashoffset，结果是谁也压不住谁的抖动；像进度环那样，rAF 播放期间用 class 关掉 transition，播完再恢复，是标准解法；
  • rAF 必须在卸载时取消：SPA 里组件销毁后帧回调照样执行，轻则空跑耗性能，重则操作已卸载的 DOM 报错；本页两个组件都在 onBeforeUnmount 里 cancelAnimationFrame；
  • getTotalLength 别在帧循环里调：路径不变时总长恒定，每帧调用纯属浪费；在路径生成时量一次缓存起来，路径更新再重新量；
  • fill="none" 的图形点不中：默认命中规则只认实际绘制的像素，空心圆环的内侧点击会穿透；用 fill="transparent" 或 pointer-events="all" 扩大命中区，tooltip 触发区常用这招加宽细线的可点范围；
  • 节点规模决定技术选型：几十个节点动画 SVG 游刃有余，上千节点每帧改属性就会卡在样式重算上；正弦波演示下方的成本提示给出了规模判断思路，更深的量化数据见性能对比。

小结 ​

要点回顾：SVG 动画有 CSS、SMIL、JS 三条路线，SMIL 已停止演进，新项目在 CSS transition、WAAPI、rAF 之间按复杂度选择；transform 动画牢记 transform-box: fill-box；描边动画等于 dasharray 取周长加 dashoffset 归零；事件命中默认只认绘制像素，fill:none 要用透明填充或 pointer-events 补救；卸载组件必须取消 rAF。

至此 SVG 三章完结。下一章进入 Fabric.js 核心对象模型：它在 Canvas 之上封装出类似 SVG 的对象树与交互体系，兼顾保留模式的易用与位图的性能。
