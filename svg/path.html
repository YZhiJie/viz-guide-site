3.2 Path 与贝塞尔曲线 ​

path 是 SVG 中最强大的元素：前面学过的所有形状都能用它表达，它还额外覆盖任意曲线、弧线与不规则轮廓——图标本体、地图边界、手写笔迹几乎都是 path。本页拆解 d 属性的命令体系、三次贝塞尔曲线的几何直觉，以及 getTotalLength 这对实用 API，最后用一个可拖拽的贝塞尔编辑器把直觉变成手感。

概念解析 ​

path 是什么 ​

path 元素把整张图形压缩进一个 d 属性：一串命令字母加坐标数字，像给画笔下达的指令序列——"抬笔到 (10,10)，直线到 (90,10)，三次曲线到 ……"。其余五种形状都只是 path 的语法糖：矩形可以写成四条 L，圆可以写成两段 A。

为什么需要这样一门"迷你语言" ​

图形世界里的轮廓远比规则形状复杂：一枚图标由十几段直线与曲线拼接而成，一段手绘签名是上百个采样点的平滑连接。为每种轮廓都发明新标签不现实，path 用一套正交的命令组合出任意形态，是 SVG 表达能力的上限所在。反过来说，读懂 d 字符串，就拿到了绝大多数矢量资源的钥匙。

典型应用场景 ​

  • 图标与 LOGO：设计软件导出的矢量资源几乎全部是 path；
  • 平滑折线图：把离散数据点用贝塞尔连成平滑曲线，图表库的标配；
  • 描边动画：签名书写、进度描边，依赖路径长度计算（下一页展开）；
  • 不规则区域：地图版块、热力轮廓、裁切形状。

核心 API 与原理 ​

d 命令详解 ​

命令分绝对（大写字母，坐标相对原点）与相对（小写字母，坐标相对当前点）两版，参数个数固定：

命令参数说明迷你示例
M / mx y抬笔移动到起点，一条路径必须以它开始M 10 10
L / lx y直线到目标点L 90 10
H / hx水平线到指定横坐标H 90
V / vy垂直线到指定纵坐标V 90
C / cx1 y1 x2 y2 x y三次贝塞尔：两个控制点加一个终点C 20 20, 40 20, 50 10
S / sx2 y2 x y平滑三次：第一控制点自动镜像S 80 20, 90 10
Q / qx1 y1 x y二次贝塞尔：一个控制点Q 50 30, 90 10
T / tx y平滑二次：控制点自动镜像T 130 10
A / arx ry 旋转 大弧 顺逆 x y椭圆弧到终点，参数最多A 30 30 0 0 1 90 90
Z / z无闭合：直线回到本段路径起点Z

一个综合小例：从 (20,80) 出发，直线到 (80,80)，三次曲线到 (140,40)，再闭合回起点：

html
<svg viewBox="0 0 160 100" width="320" height="200">
  <!-- 三角形轮廓被"顶起"成圆弧顶：先直线、再三贝塞尔、最后 Z 闭合 -->
  <path d="M 20 80 L 80 80 C 100 80, 140 70, 140 40 Z"
        fill="#5b9cf5" stroke="#1a4480" stroke-width="2" />
</svg>

A 命令：参数最多的特例 ​

椭圆弧的完整形式是 A rx ry x-axis-rotation large-arc-flag sweep-flag x y，共七个参数。前三个描述椭圆本身（两轴半径与整体旋转角），后两个布尔旗标解决一个几何歧义：过两点且半径确定的椭圆弧有四条候选，large-arc-flag 决定取大弧（1）还是小弧（0），sweep-flag 决定按顺时针（1）还是逆时针（0）方向画。两个旗标只有 0 和 1 两个合法值，写其他数字会被静默容错，排查困难。

三次贝塞尔的几何直觉 ​

三次贝塞尔由四个点确定：起点 P0、终点 P3，以及两个不在曲线上的控制点 P1、P2。它的行为有两条核心规律：

  • 控制点决定端点处的切线方向：曲线离开 P0 时，运动方向必然沿着 P0 指向 P1 的连线；进入 P3 时，必然沿着 P2 指向 P3 的连线。想控制曲线"出发的朝向"，就摆控制点；
  • 控制点离端点越远，拉力越强：曲线被控制点"吸"过去的程度与控制柄长度正相关，P1 拉得远，曲线前段就更贴近 P0→P1 的方向。

把 P1、P2 分别放在曲线两侧，就能捏出 S 形；放在同侧则是 C 形或 U 形。字体轮廓、贝塞尔钢笔工具，本质都是这两条规律的反复运用。

S 命令的反射规则 ​

连续绘制多段三次贝塞尔时，S 命令省去第一个控制点：它自动把前一段 C 或 S 的第二控制点，关于当前端点做镜像，作为本段的第一控制点。镜像保证了两段曲线在连接点处切线方向一致——视觉上就是平滑无拐点。若前面不是 C/S 命令，第一控制点退化为与起点重合，本段从"零切向"出发。

Q 与 C 的升阶关系 ​

二次贝塞尔只有一个控制点 Q，能表达的弯曲有限，但可以无损升阶为三次：保持端点不变，两个三次控制点取

js
// Q 升阶为 C：P0/P3 为端点，Q 为二次控制点
const c1 = { x: p0.x + (2 / 3) * (q.x - p0.x), y: p0.y + (2 / 3) * (q.y - p0.y) }
const c2 = { x: p3.x + (2 / 3) * (q.x - p3.x), y: p3.y + (2 / 3) * (q.y - p3.y) }

画出的曲线与原来的二次贝塞尔完全重合。凡是"只支持三次"的场景（如 Canvas 的 bezierCurveTo），遇到二次数据就用这个公式转换。

getTotalLength 与 getPointAtLength ​

path 元素自带两个按弧长操作的 DOM API：

js
const path = document.querySelector('path')
const total = path.getTotalLength()        // 路径总长度（用户坐标系单位）
const mid = path.getPointAtLength(total / 2) // 弧长中点处的坐标 { x, y }

它们是两件重要工作的地基：下一页的描边动画要用总长设置 dasharray 与 dashoffset；沿路径运动（让元素沿线飞行）则每帧取 getPointAtLength(progress * total) 得到当前位置。两点注意：返回长度不带单位缩放，viewBox 缩放不影响它；每次调用都有计算成本，总长应缓存。

折线转平滑曲线的思路 ​

图表里把离散数据点连成平滑曲线的经典做法是 Catmull-Rom 样条：对每个数据点，取左右相邻点连线方向的若干分之一作为该点的切线方向，推出两个三次控制点，相邻两点之间正好一段 C。理解本页的"控制点决定切向"之后，这个算法就不再神秘——它只是在每个数据点处程序化地摆放控制柄。

核心代码与组件逻辑一致，可直接复制复用：

vue
// 文件: docs/.vitepress/components/svg/SvgPath.vue
<template>
  <div class="demo-card">
    <div class="stage">
      <svg
        ref="svgRef"
        viewBox="0 0 480 300"
        class="stage-svg"
        role="img"
        aria-label="三次贝塞尔曲线编辑器"
        @pointerdown="onPointerDown"
        @pointermove="onPointerMove"
        @pointerup="onPointerUp"
        @pointercancel="onPointerUp"
      >
        <!-- 控制柄连线：端点与各自控制点之间的虚线 -->
        <line :x1="pts[0].x" :y1="pts[0].y" :x2="pts[1].x" :y2="pts[1].y" class="handle-line" />
        <line :x1="pts[3].x" :y1="pts[3].y" :x2="pts[2].x" :y2="pts[2].y" class="handle-line" />
        <!-- 贝塞尔曲线本体：d 由四个特征点实时计算 -->
        <path :d="pathD" class="curve" />
        <!-- 两个端点（大圆）与两个控制点（小圆），data-idx 标记索引供拖拽识别 -->
        <circle :cx="pts[0].x" :cy="pts[0].y" r="9" class="endpoint" data-idx="0" />
        <circle :cx="pts[3].x" :cy="pts[3].y" r="9" class="endpoint" data-idx="3" />
        <circle :cx="pts[1].x" :cy="pts[1].y" r="7" class="ctrl-point" data-idx="1" />
        <circle :cx="pts[2].x" :cy="pts[2].y" r="7" class="ctrl-point" data-idx="2" />
      </svg>
    </div>
    <p class="d-string">当前 d：<code v-text="pathD"></code></p>
  </div>
</template>

<script setup>
import { ref, computed } from 'vue'

// 四个特征点的初始位置：P0/P3 为端点，P1/P2 为控制点，初值固定保证 SSR 一致
const initialPts = [
  { x: 60, y: 240 },
  { x: 140, y: 60 },
  { x: 340, y: 60 },
  { x: 420, y: 240 },
]
const pts = ref(initialPts.map((p) => ({ ...p })))
const dragIndex = ref(-1) // 正在拖拽的点索引，-1 表示空闲
const svgRef = ref(null)

// 由四个点实时拼出三次贝塞尔的 d 字符串
const pathD = computed(() => {
  const [p0, p1, p2, p3] = pts.value
  return `M ${p0.x} ${p0.y} C ${p1.x} ${p1.y}, ${p2.x} ${p2.y}, ${p3.x} ${p3.y}`
})

// 屏幕坐标换算为 SVG 用户坐标：getScreenCTM 的逆矩阵天然兼容 viewBox 缩放
function toSvgPoint(evt) {
  const ctm = svgRef.value.getScreenCTM()
  if (!ctm) return null
  const p = new DOMPoint(evt.clientX, evt.clientY).matrixTransform(ctm.inverse())
  return {
    x: Math.min(470, Math.max(10, Math.round(p.x))),
    y: Math.min(290, Math.max(10, Math.round(p.y))),
  }
}

function onPointerDown(evt) {
  const idx = evt.target.dataset ? evt.target.dataset.idx : undefined
  if (idx === undefined) return
  dragIndex.value = Number(idx)
  // 捕获指针：之后即使移出圆点，move/up 事件仍派发给 svg
  svgRef.value.setPointerCapture(evt.pointerId)
}
function onPointerMove(evt) {
  if (dragIndex.value < 0) return
  const p = toSvgPoint(evt)
  if (!p) return
  pts.value[dragIndex.value] = p
}
function onPointerUp() {
  dragIndex.value = -1
}
</script>

最佳实践与常见坑 ​

  • 复制粘贴路径段时优先小写相对命令：相对坐标以当前点为基准，整段移动位置时无需重算内部坐标；绝对命令平移后所有数字都要跟着改，自动生成时反而推荐绝对命令——没有累积误差；
  • 一条 A 命令画不出整圆：起点与终点重合时弧线被退化为"没有弧"，标准做法是拆成两条半圆弧（两段 A 各画 180 度），圆环、饼图的扇区都遵循这个套路；
  • 别把控制点当成曲线上的点：贝塞尔曲线只经过两个端点，控制点是"磁铁"；需要曲线精确经过某个中间点时，应反解控制点位置（如 Catmull-Rom），而不是把控制点直接放在目标处；
  • 开放路径设 fill 会被"脑补闭合"：path 没有 Z 但给了填充色时，浏览器按首尾自动连线后的区域填色，经常涂出意外的多边形；纯描边路径显式写 fill="none"；
  • d 字符串注意精度与体积：设计软件导出的路径常带五六位小数，文件体积成倍膨胀，上线前用 svgo 等工具压缩精度（保留一到两位小数通常足够）；
  • getTotalLength 的结果要缓存：它按当前 d 计算，路径不变则结果不变，每帧重复调用纯属浪费；路径更新后再重新取值，并留意它返回的是用户坐标系长度，与屏幕像素之间隔着 viewBox 缩放。

小结 ​

要点回顾：path 用 d 属性的命令序列描述任意图形，M/L/H/V/C/S/Q/T/A/Z 十个命令覆盖直线、贝塞尔与椭圆弧，大写绝对、小写相对；三次贝塞尔的控制点决定端点切向与拉力，S 命令靠反射保持连接处平滑，Q 可无损升阶为 C；getTotalLength 与 getPointAtLength 是描边动画与沿线运动的基础设施；平滑折线的本质是程序化摆放控制柄。
