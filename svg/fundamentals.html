3.1 SVG 基础与 viewBox ​

SVG（Scalable Vector Graphics）是用 XML 标签描述图形的矢量图形语言，浏览器把它解析成一棵常驻内存的节点树——这正是可视化全景中讲过的"保留模式"。本页把 SVG 上手所需的最小集合讲全：三种嵌入方式的能力差异、形状元素速查、fill 与 stroke 样式体系、viewBox 坐标映射，以及 defs 渐变定义，为后面两页的 path 与动画打地基。

概念解析 ​

SVG 是什么 ​

SVG 是一份描述图形的 XML 文档：rect、circle、path 等标签声明"这里有一个什么图形"，属性声明它的位置、大小与颜色。浏览器解析后生成一棵图形对象树——每个标签都是一个真实节点，常驻文档中，改属性画面即更新，CSS 可以选中它，事件可以挂在它身上。

这与 Canvas 的立即模式构成根本分野，三种方式画柱状图一页已经直观对比过：同一张柱状图，SVG 版本里每根柱子是可以 hover、可以点击的 DOM 节点，而 Canvas 版本里柱子只是画布上的一堆像素。矢量特性则意味着图形由几何公式描述，任意缩放都重新栅格化，永远不会出现位图拉伸的锯齿。

三种嵌入方式的能力差异 ​

同一份 SVG 资源，嵌入页面的方式不同，能力天差地别：

嵌入方式写法DOM 可访问CSS 可定制事件交互脚本化
内联 SVG直接把 svg 标签写进 HTML是完全参与页面样式支持支持
img 引用img 标签的 src 指向 .svg 文件否（独立文档）只能用文件内部样式不支持不支持
CSS 背景background-image: url(x.svg)否否不支持不支持

结论很直接：凡是要交互、要主题换色、要 JS 驱动的 SVG，必须内联；img 与背景方式适合纯装饰性的图标与插画。工程上的折中是 SVG Sprite——把多个图标定义进 symbol 元素，页面里用 use 标签引用，既保留内联能力又避免重复粘贴整段 XML。

典型应用场景 ​

  • 图标系统：svg sprite 加 use 引用已是主流方案，矢量级清晰、可用 currentColor 跟随文字换色；
  • LOGO 与插画：无限缩放不失真，一套资源适配所有屏幕密度；
  • 中小规模图表：D3.js 等库的默认渲染目标，节点级交互天然免费；
  • 流程图、拓扑图、关系图：节点连线场景下，每个图元都要响应 hover 与拖拽，保留模式的对象模型正合适。

核心 API 与原理 ​

形状元素速查 ​

SVG 内置六种基础形状，全部通过属性描述几何：

元素关键属性说明
rectx, y, width, height, rx矩形，rx/ry 控制圆角半径
circlecx, cy, r圆，圆心加半径
ellipsecx, cy, rx, ry椭圆，两轴半径可不同
linex1, y1, x2, y2线段，只有描边没有填充
polylinepoints折线，顶点坐标串，首尾不闭合
polygonpoints多边形，自动把首尾连成闭合区域
html
<svg viewBox="0 0 400 300" width="400" height="300">
  <!-- 圆角矩形：左上角 (24,24)，宽 90 高 64，圆角半径 6 -->
  <rect x="24" y="24" width="90" height="64" rx="6" fill="#5b9cf5" />
  <!-- 圆：圆心 (326,58)，半径 38，只描边不填充 -->
  <circle cx="326" cy="58" r="38" fill="none" stroke="#d9564f" stroke-width="3" />
  <!-- 折线与多边形共用 points 语法："x1,y1 x2,y2 ..." -->
  <polyline points="24,150 84,104 144,158 204,112" fill="none" stroke="#3fa96f" />
  <polygon points="272,186 330,116 384,196" fill="#f0a020" />
</svg>

注意坐标系的朝向：与 Canvas 一致，y 轴向下为正，原点在左上角，这与坐标系与 DPR一页讲过的屏幕坐标传统相同。

fill 与 stroke 样式体系 ​

SVG 图形的上色分两套：fill 管内部填充，stroke 管轮廓描边。每个属性既可以直接写成标签属性（称为表现属性），也可以写进 CSS：

css
/* CSS 写法：优先级高于标签上的表现属性 */
.my-rect {
  fill: #2f7ae5;              /* 填充色，可用 currentColor 跟随文字色 */
  stroke: #1a4480;            /* 描边色 */
  stroke-width: 2;            /* 描边宽度 */
  stroke-dasharray: 10 6;     /* 虚线：画 10 空 6 循环 */
  stroke-linecap: round;      /* 线端：butt | round | square */
  stroke-linejoin: round;     /* 转角：miter | round | bevel */
  fill-opacity: 0.6;          /* 填充透明度，独立于整体 opacity */
}

优先级从高到低：内联 style 大于 CSS 规则大于表现属性。一个高频坑是：标签上写了 fill="red"，样式表里的 fill 却照样生效——因为表现属性的优先级在 CSS 面前最低。

另一个重要特性是可继承：fill、stroke、font-size 等多数表现属性会沿节点树向下继承。在 g 分组标签上统一设置 fill，组内所有图形默认跟随，子节点再按需覆盖——这正是图标能用 currentColor 换色的原理。

viewBox：世界与窗口 ​

viewBox="minX minY width height" 四个数字定义了 SVG 的用户坐标系，可以理解为"从图形世界里截取哪一块来显示"：

  • 前两个数是窗口左上角的坐标，增大它们相当于把窗口向右、向下平移；
  • 后两个数是窗口的宽与高，窗口越小，同样内容在屏幕上放得越大——这是反直觉的一点：viewBox 宽度从 400 改成 200，等于拿放大镜只看世界的一半，视觉上图形放大一倍。

viewBox 与 CSS 尺寸（viewport）是两套体系：viewBox 声明"看哪一块"，CSS 宽高声明"显示多大"，浏览器自动在两者之间建立缩放与平移变换。只写 width/height 不写 viewBox 时，SVG 按 1:1 像素映射，超出部分直接裁切，图形不会随容器缩放——加上 viewBox，SVG 才真正获得"矢量缩放"能力。

preserveAspectRatio 决定 viewBox 区域与 viewport 宽高比不一致时的对齐策略，取值为"对齐方式 + 适配模式"的组合：

值行为
xMidYMid meet（默认）等比缩放至完整可见，居中，可能留白边
xMidYMid slice等比缩放至铺满，居中，超出部分裁掉
none拉伸填满，图形变形
xMinYMin meet 等对齐位置可换为 Min/Mid/Max 的九种组合

meet 像"完整照片装进相框"，slice 像"铺满屏幕的壁纸"。本页演示组件故意给 svg 加了背景色，拖动窗口宽滑块时能看到 meet 模式留下的空白带。

defs 与渐变 ​

defs 是"定义区"：里面的内容不直接渲染，专供其他元素通过 url(#id) 引用——渐变、图案、裁切路径都放这里。

html
<defs>
  <!-- 线性渐变：x1,y1 到 x2,y2 定义渐变轴，stop 定义色标 -->
  <linearGradient id="my-grad" x1="0" y1="0" x2="1" y2="1">
    <stop offset="0" stop-color="#2f7ae5" />
    <stop offset="1" stop-color="#8a63d2" />
  </linearGradient>
  <!-- 径向渐变：圆心向外扩散，常做光晕 -->
  <radialGradient id="my-radial" cx="0.5" cy="0.5" r="0.5">
    <stop offset="0" stop-color="#fff3b0" />
    <stop offset="1" stop-color="#f0a020" />
  </radialGradient>
</defs>
<rect width="200" height="100" fill="url(#my-grad)" />

渐变坐标默认使用 objectBoundingBox 单位（0 到 1 相对图形包围盒），需要绝对定位渐变轴时把 gradientUnits 设为 userSpaceOnUse，坐标即按用户坐标系解释。

至于滤镜：filter 元素用高斯模糊、颜色矩阵等原语组成效果链，能力强大，但会触发离屏位图运算，大面积使用性能开销不小，本教程点到为止。

完整代码示例 ​

下面是一个 viewBox 交互实验台：固定一组图形（矩形、圆、折线、多边形、文字）构成"世界"，三个滑块分别控制 viewBox 的 x 偏移、y 偏移与窗口宽度，窗口高度按 4:3 联动。虚线框标出世界边界，方便观察窗口的移动与缩放。

当前 viewBox：0 0 400 300（高度按 4:3 随宽度联动）

<script setup>
import { ref, computed } from 'vue'

// viewBox 的三个可调分量：x/y 决定窗口左上角，width 决定窗口宽度，初值固定保证 SSR 一致
const vbX = ref(0)
const vbY = ref(0)
const vbW = ref(400)

// 响应式绑定 viewBox 属性：这正是 SVG 保留模式"改数据即更新画面"的体现
const viewBox = computed(() => {
  const h = Math.round(vbW.value * 0.75)
  return `${vbX.value} ${vbY.value} ${vbW.value} ${h}`
})
</script>

最佳实践与常见坑 ​

  • viewBox 与 CSS 尺寸必须成对考虑：只设 width/height 不设 viewBox，SVG 按像素 1:1 映射，超出即裁切，容器变大图形纹丝不动——很多人以为"矢量图天然自适应"，其实自适应能力是 viewBox 给的；响应式布局的常见写法是只给 viewBox，CSS 控制宽高；
  • 别用表现属性对抗 CSS：标签上写死 fill="red" 之后，想通过换主题改色时会发现 CSS 覆盖不了内联 style 以外的写法其实能覆盖表现属性，但团队协作中两套写法混用必然失控；约定"颜色一律走 CSS、几何属性留在标签上"是最省心的分工；
  • 渐变 id 在整页范围内必须唯一：url(#id) 引用按文档顺序取第一个匹配节点，同页多个 SVG 若撞了 id，后者会引用到前者的渐变；更隐蔽的是引用 display:none 的 SVG 里的渐变，某些浏览器直接渲染失败——组件化开发时给 id 加组件名前缀；
  • text 元素没有盒模型：不会自动换行、没有宽高，多行文字要用 tspan 逐行定位，或者干脆用 foreignObject 嵌入 HTML；文字垂直居中用 dominant-baseline 配合 dy 微调，别拿 HTML 的行高思维套；
  • polyline 与 polygon 只差一个闭合：polygon 自动把首尾相连并填充内部，polyline 首尾断开；给 polyline 设 fill 会看到一个"脑补闭合"的怪异填色，纯线条场景务必显式 fill="none"；
  • 嵌套 SVG 里的百分比相对最近的 viewport：内层 svg 元素的 x、y、width 用百分比时，参照系是外层 svg 建立的 viewport 而非整个页面，层层嵌套时容易算错，能写绝对坐标就写绝对坐标。

小结 ​

要点回顾：SVG 是 XML 描述的矢量图形语言，保留模式让节点常驻、CSS 与事件天然参与；内联嵌入才有完整的交互与样式能力；六种基础形状加 fill/stroke 样式体系覆盖大部分静态图形需求；viewBox 定义用户坐标系的取景窗口，preserveAspectRatio 决定它与 CSS 尺寸的映射策略；defs 加渐变是复用定义的标准姿势。
