4.2 交互与编辑器能力 ​

4.1 建立了对象模型认知，本节进入 fabric 最有价值的部分：编辑器交互。变换控件、事件流、自由绘制是标注工具、白板、在线设计器这类产品的共同地基，理解它们之后，"给图形加交互"就从手写状态机变成了配置题。

概念解析 ​

变换控件体系 ​

点选对象后 fabric 会自动渲染一套变换控件：8 个缩放手柄（四角加四边）加 1 个旋转控制点，并内置 Shift 约束比例、围绕中心旋转等开箱行为。控件的具体分工：四个角手柄做双轴缩放，四个边手柄做单轴缩放，顶部的旋转控制点围绕对象中心旋转。这些控件画在 4.1 提到的上层交互画布上，不污染业务渲染。这里有一个贯穿全库的关键设计：

  • 手柄拖动改变的是 scaleX / scaleY，width / height 保持不变；
  • 宽高是"形状定义"，缩放是"变换状态"，两者叠加表达最终视觉尺寸；
  • 因此一切几何计算（边界、碰撞、导出）都必须经过 getScaledWidth() / getScaledHeight() 换算。

如需把缩放"固化"回宽高（导出数据时很常见），可以在 object:modified 回调里读取 scale 并做一次归一换算，再重置 scaleX/scaleY 为 1。理解了"定义与变换分离"，fabric 的大量 API 设计就都顺理成章了。

js
canvas.on('object:modified', (opt) => {
  const obj = opt.target
  if (obj.scaleX === 1 && obj.scaleY === 1) return
  // 把缩放固化回宽高：宽高乘上 scale，scale 归一，业务模型只认宽高
  obj.set({
    width: obj.getScaledWidth(),
    height: obj.getScaledHeight(),
    scaleX: 1,
    scaleY: 1
  })
  obj.setCoords() // 几何变了必须刷新包围盒缓存，否则命中检测错位
})

事件体系 ​

fabric 的事件分三层，按需订阅即可：

层级事件典型用途
画布级指针mouse:down / mouse:move / mouse:up自定义点击行为、绘制预览
对象变换object:moving / object:scaling / object:rotating（过程高频）与 object:modified（结束收尾）边界限制、实时联动、压撤销栈
集合与选中object:added / object:removed、selection:created / selection:updated / selection:cleared属性面板同步、增删记录

回调参数的两个高频字段：opt.target 只有命中对象时才有值，为空即点击了空白画布；opt.pointer 是相对画布的坐标。v6 需要注意：pointer 已被标记为兼容保留，新代码推荐使用 opt.scenePoint（对象树所在场景坐标）与 opt.viewportPoint（视口原始坐标）——在没有视口变换时两者等价，一旦用 setViewportTransform 缩放平移画布，选错坐标系就会算错位置。

另外 selection:created / selection:updated 的 opt.selected 是数组：用户按住 Shift 框选多个对象时长度大于 1，只取第一项会丢掉多选状态。

把一次拖动的完整事件时序排出来，三类事件的关系就清楚了：

js
// 一次"拖动矩形"的完整时序
// mouse:down —— 命中矩形，opt.target 有值
//   -> object:moving —— 每帧触发，opt.pointer 提供实时坐标
//   -> object:modified —— 抬笔收尾，整个过程只触发一次

// 一次"空白处按下、拖出框选"的时序
// mouse:down（opt.target 为空）-> mouse:up -> selection:created（opt.selected 为数组）

// 画布级三件套的经典模式：实现"框选出矩形"的预览绘制
let preview = null
canvas.on('mouse:down', (opt) => {
  preview = new Rect({
    left: opt.pointer.x, top: opt.pointer.y, width: 1, height: 1,
    fill: 'rgba(96, 125, 255, 0.3)'
  })
  canvas.add(preview)
})
canvas.on('mouse:move', (opt) => {
  if (!preview) return
  preview.set({ width: Math.abs(opt.pointer.x - preview.left), height: Math.abs(opt.pointer.y - preview.top) })
  canvas.requestRenderAll()
})
canvas.on('mouse:up', () => { preview = null })

选中态与多选 ​

程序化控制选中只有三个方法：setActiveObject(obj) 选中、discardActiveObject() 清空、getActiveObject() 读取。用户按 Shift 点选或框选多个对象时，getActiveObject() 返回的是 ActiveSelection 组合对象——它也是 FabricObject 子类，可以整体拖动缩放，但它是临时对象：序列化、业务导出、批量删除时都要用 getObjects() 拆开逐一处理，把 ActiveSelection 本身存进 JSON 是常见错误（4.3 实战会再遇到它）。

自由绘制 PencilBrush ​

三行代码开启画笔模式：

js
canvas.isDrawingMode = true
canvas.freeDrawingBrush.color = '#2563eb'
canvas.freeDrawingBrush.width = 4

进入画笔模式后，鼠标按下即在交互层实时绘制轨迹；抬笔时轨迹被固化为一个 Path 对象加入对象树，并触发 path:created 事件。这意味着笔迹立刻获得 fabric 对象的一切能力：可选中、可拖动、可序列化进 toJSON()。v6 的关键差异：画布不再自动创建默认画笔，必须显式赋值 canvas.freeDrawingBrush = new PencilBrush(canvas)，否则 isDrawingMode 打开了也画不出任何东西。

画笔还有两个实用选项：freeDrawingBrush.strokeDashArray 画虚线笔迹、freeDrawingBrush.shadow 给笔迹加阴影。path:created 回调里的 opt.path 就是刚生成的 Path 对象——可以立即修改样式，也可以在不需要时 remove 掉，用它就能实现"撤销上一笔"。

绘图模式与选择模式互斥 ​

isDrawingMode 为 true 时，鼠标按下直接进入绘制管线，不再执行命中检测与选中逻辑——画笔与对象选择天然互斥，一个画布同一时刻只能处于一种模式。移动端同理：isDrawingMode 决定触摸轨迹是画笔迹还是拖动对象。工程上的两个配套动作：切换回选择模式时调用 discardActiveObject() 清掉残留的选中控制框；切到画笔模式时确认画笔实例与样式已就绪。

工程技巧：边界 clamp 与吸附 ​

object:moving 里把坐标夹紧在画布范围内，是最常用的一条工程技巧（必须用缩放后的尺寸）：

js
canvas.on('object:moving', (opt) => {
  const obj = opt.target
  const w = obj.getScaledWidth()
  const h = obj.getScaledHeight()
  obj.set({
    left: Math.min(Math.max(obj.left, 0), canvas.width - w),
    top: Math.min(Math.max(obj.top, 0), canvas.height - h)
  })
})

对齐吸附是同一思路的延伸：在 object:moving 里检测对象边缘与其他对象边缘（或网格线）的横向、纵向距离，小于阈值（例如 5px）时把坐标改写为参考线位置，同时画一条临时参考线预览——白板类产品的"磁吸"效果核心代码不超过几十行。最小可行的网格吸附长这样：

js
// 网格吸附：moving 时把坐标按 10px 网格取整
canvas.on('object:moving', (opt) => {
  const obj = opt.target
  obj.set({
    left: Math.round(obj.left / 10) * 10,
    top: Math.round(obj.top / 10) * 10
  })
})

核心 API 与原理 ​

  • canvas.on(event, handler) / canvas.off(event, handler)：事件订阅与解除，回调参数统一从 opt 解构；
  • canvas.isDrawingMode：绘制模式总开关，与选择模式互斥；
  • new PencilBrush(canvas)：v6 必须手动创建并赋给 canvas.freeDrawingBrush，支持 color、width、strokeDashArray（虚线笔迹）等样式；
  • canvas.discardActiveObject()：清空选中态，模式切换与程序化删除后都应调用；
  • canvas.getActiveObject()：取当前选中对象，Shift 多选时返回 ActiveSelection 组合对象，用 getObjects() 拆开处理；
  • object.getScaledWidth() / getScaledHeight()：缩放后的实际占位尺寸，clamp 与导出换算的唯一正确来源。

完整代码示例 ​

事件日志（最近 8 条，最新在上）

mouse:move 触发过于频繁，日志中已过滤

试试：先在"选择模式"拖动矩形贴向画布边缘，观察事件日志里的 object:moving 坐标被 clamp 挡住；切到"画笔模式"换颜色、调粗细画几笔，抬笔后切回选择模式，笔迹已成为可选中、可拖动、可缩放的 Path 对象。

核心代码（与上方演示一致的精简版，可直接放入任意 SFC 的 script setup）：

js
// 文件: docs/.vitepress/components/fabric/FabricDraw.vue
// 说明：以下为 script setup 核心逻辑；模板部分是一个演示卡片，
// 包含模式切换按钮、画笔颜色与粗细控制、canvas 画布与事件日志面板
import { ref, onMounted, onBeforeUnmount } from 'vue'

let fabricCanvas = null
let fabricLib = null

const mode = ref('select') // 'select' | 'draw'
const brushColor = ref('#111827')
const brushWidth = ref(4)
const logs = ref([]) // 事件日志：最近 8 条，最新在上

function pushLog(name, target, point) {
  logs.value.unshift({
    name,
    target: target || '画布',
    pos: point ? Math.round(point.x) + ', ' + Math.round(point.y) : '-'
  })
  if (logs.value.length > 8) logs.value.pop()
}

// 模式切换：绘图与选择互斥，由 isDrawingMode 一个开关控制
function setMode(next) {
  mode.value = next
  fabricCanvas.isDrawingMode = next === 'draw'
  if (next === 'draw' && !fabricCanvas.freeDrawingBrush) {
    // v6 不再自动创建默认画笔：不显式赋值就画不出来
    fabricCanvas.freeDrawingBrush = new fabricLib.PencilBrush(fabricCanvas)
    applyBrushStyle()
  }
  if (next === 'select') {
    fabricCanvas.discardActiveObject() // 清掉残留选中框
    fabricCanvas.requestRenderAll()
  }
}

// 把色板与滑块同步到画笔；抬笔生成的 Path 会继承这些样式
function applyBrushStyle() {
  const brush = fabricCanvas.freeDrawingBrush
  if (!brush) return
  brush.color = brushColor.value
  brush.width = brushWidth.value
}

onMounted(async () => {
  const { Canvas, Rect, PencilBrush } = await import('fabric')
  if (!canvasRef.value || !wrapRef.value) return // 动态加载期间组件可能已卸载
  fabricLib = { PencilBrush }

  const width = Math.min(wrapRef.value.clientWidth || 640, 640)
  fabricCanvas = new Canvas(canvasRef.value, {
    width,
    height: Math.round(width * 0.625),
    backgroundColor: '#ffffff'
  })

  // 画布级指针事件：opt.target 有值即命中对象，opt.pointer 为兼容字段
  fabricCanvas.on('mouse:down', (opt) => pushLog('mouse:down', opt.target && opt.target.type, opt.pointer))
  fabricCanvas.on('mouse:up', (opt) => pushLog('mouse:up', opt.target && opt.target.type, opt.pointer))

  // 拖动过程高频触发：顺手做边界 clamp 并记录日志
  fabricCanvas.on('object:moving', (opt) => {
    const obj = opt.target
    if (!obj) return
    // 必须用缩放后尺寸夹紧边界，用 width/height 会漏算手柄缩放
    const w = obj.getScaledWidth()
    const h = obj.getScaledHeight()
    obj.set({
      left: Math.min(Math.max(obj.left, 0), fabricCanvas.width - w),
      top: Math.min(Math.max(obj.top, 0), fabricCanvas.height - h)
    })
    pushLog('object:moving', obj.type, opt.pointer)
  })

  fabricCanvas.on('object:modified', (opt) => pushLog('object:modified', opt.target && opt.target.type, null))
  fabricCanvas.on('object:added', (opt) => pushLog('object:added', opt.target && opt.target.type, null))
  fabricCanvas.on('selection:created', () => pushLog('selection:created', fabricCanvas.getActiveObject().type, null))
  fabricCanvas.on('selection:cleared', () => pushLog('selection:cleared', null, null))
  // 自由绘制抬笔：轨迹固化为 Path 对象并进入对象树
  fabricCanvas.on('path:created', (opt) => pushLog('path:created', opt.path && opt.path.type, null))

  // 预置一个矩形，让选择模式一进来就有对象可拖
  const first = new Rect({ width: 130, height: 84, fill: 'rgba(96,125,255,0.85)', rx: 8, ry: 8 })
  first.set({ left: 50, top: 50 })
  fabricCanvas.add(first)
})

onBeforeUnmount(() => {
  if (fabricCanvas) {
    fabricCanvas.dispose()
    fabricCanvas = null
  }
})

最佳实践与常见坑 ​

  • 画不出笔迹先查 freeDrawingBrush 是否赋值。v6 构造画布时不再内置默认画笔（v5 有），isDrawingMode = true 而 brush 为 undefined 时绘制管线直接短路。这是从 v5 教程迁移过来最常见的"什么都没发生"。
  • 高频事件里不要做重活。object:moving 与 mouse:move 每帧触发，里面做序列化、布局计算或 Vue 深层响应式更新会直接掉帧；重活统一放到 object:modified 收尾，过程事件只做轻量的坐标改写与状态记录。
  • clamp 必须用 getScaledWidth / getScaledHeight。直接读 width/height 时，用户缩放过的对象仍能被拖出一半——因为视觉宽度早已是宽高乘以 scale 的结果。
  • opt.pointer 已弃用，注意坐标系迁移。v6 新代码用 opt.scenePoint / opt.viewportPoint；只要涉及视口变换（缩放平移画布），两个坐标系的差异就会显现，写死 pointer 的旧代码在缩放画布上会出现命中偏移。
  • selection:created 的 opt.selected 是数组。只处理第一项会在 Shift 多选场景丢失其余对象，属性面板与批量删除都要按数组处理，或用 getActiveObject() 拿组合对象再 getObjects() 拆开。
  • 模式切换要清理选中态。从画笔切回选择模式时若不 discardActiveObject()，可能出现"控制框悬空"或选中状态与日志面板不同步的视觉 bug。
  • 事件回调之外改属性要手动重绘。object:moving 这类变换管线里的回调，fabric 会在同帧重新渲染；但在回调之外直接 obj.set() 改坐标（如程序化位移、吸附修正收尾），需要再调 requestRenderAll()，否则画面停留在旧帧。
  • 画布事件回调会持有组件闭包。canvas.on 注册的回调引用了 Vue 状态，画布不销毁回调就不释放；组件重建、画布复用的场景下，要么 dispose 要么 canvas.off 解绑，否则整条闭包链会让已卸载组件无法被垃圾回收。

小结 ​

本节要点：fabric 的变换控件通过 scaleX/scaleY 表达缩放，宽高与变换分离，几何计算必须走 getScaled 系列；事件分画布指针、对象变换、集合选中三层，v6 用 scenePoint/viewportPoint 取代 pointer；自由绘制由 PencilBrush 驱动，v6 必须显式创建画笔实例，抬笔生成可序列化的 Path；isDrawingMode 与选择模式互斥，切换时要 discardActiveObject。边界 clamp 与对齐吸附都是在 object:moving 里改写坐标的同一类技巧。下一节 4.3 实战：图片标注工具 将把这些能力组装成一个完整可用的标注工具。
