4.3 实战：图片标注工具 ​

前两节分别建立了对象模型与交互认知，本节把它们组装成一个完整可玩的图片标注工具：程序化底图、可增删的标注框、双击可改的标签文本、一键导出业务 JSON。这个小工具是 fabric 能力模型的缩影——做完它，绝大多数"画布编辑器"类需求都能套用同一套骨架。

概念解析 ​

需求拆解 ​

把"图片标注工具"拆成四个模块，每个模块对应 fabric 的一块能力：

模块需求fabric 能力
底图层照片铺满画布、永不响应交互FabricImage + selectable/evented 关闭
标注框层可添加、拖动、缩放、旋转、删除Rect + 变换控件 + ActiveSelection
标签文本显示名称、双击修改IText 内置双击进入编辑
数据导出只导出业务字段 {x, y, w, h, label}getObjects 遍历 + 属性换算

分层的关键在"谁参与交互"：底图彻底退出事件系统，标注对象独占选中权，这样用户永远不会出现"点了一下结果选中了照片"的困惑。

这套骨架的扩展点也一目了然：吸附与网格对齐挂在 object:moving（见 4.2 的工程技巧）；需要记录旋转就在导出结构里补 angle 字段；多边形标注用 Polygon 对象或自由绘制实现；撤销栈直接复用 4.1 的 toJSON 快照方案。业务变化动的只是"导出映射"和"新增对象类型"，fabric 层几乎不用改。

底图方案：离屏生成 + fromURL ​

真实项目里底图来自用户上传或 CDN；本教程不依赖任何外部网络资源，改用离屏 canvas 程序化生成一张 800x500 的"照片"：线性渐变天空、太阳、两座几何山形与地面色块，toDataURL() 导出 dataURL 后交给 fabric 使用：

js
const img = await FabricImage.fromURL(url) // v6 返回 Promise（v5 是回调）

拿到图片后必须做两件事：一是按画布尺寸设置 scaleX / scaleY 铺满——不要直接改 width/height，图片对象的宽高对应源图绘制区域，改它们相当于裁切；二是 img.set({ selectable: false, evented: false })，让底图不可选中、不成为事件目标，点击会穿透到上层的标注框。最后 sendObjectToBack(img) 把底图压到最底层。

清晰度方面不需要手动处理 DPR：fabric 的 enableRetinaScaling 默认开启，会按设备像素比放大画布物理像素再缩小显示，高分屏上底图与标注自动变清晰，DPR 概念回顾见 坐标系、DPR 与颜色模型。

标注框与标签：不合并 Group 的取舍 ​

一个标注由两个对象组成：Rect 本体（fill 近透明、stroke 高亮、strokeDashArray 虚线）与 IText 标签。保持两个独立对象是一个刻意的简化取舍：

  • 收益：导出时只遍历 Rect 即可，映射关系简单；标签可以拖出框外自由摆放；删除逻辑互不牵连；
  • 代价：拖动框时标签不会跟随，需要用户分开调整；
  • Group 的收益：整体拖动、缩放、旋转，序列化成单个对象，命中检测完全一致；正式产品建议用 Group 包裹，并通过 toObject(propertiesToInclude) 把业务字段挂进序列化数据。

标签用 IText 而不是自己叠加 input 元素：fabric 对 IText 内置了双击进入编辑的行为（双击触发 enterEditing），光标、选区、退格全部由库处理，工程量几乎为零。一个细节：编辑过程中 fabric 不触发 object:modified，要监听文字变化需订阅 IText 自身的 changed 事件，或像本节一样在导出时直接读取最新的 label.text。

正式产品的 Group 方案示意（本节演示刻意不用，理由见上方取舍）：

js
const { Group } = await import('fabric')
// 框与标签合成整体：拖动缩放同步，序列化成单个对象
const group = new Group([rect, label], { data: { id: 'ann-1' } }) // 业务字段挂自定义属性
canvas.add(group)
canvas.toJSON(['data']) // 导出时传 propertiesToInclude，自定义字段一并带出

导出业务 JSON 与坐标换算 ​

导出时遍历 getObjects()，只保留 Rect 并映射成业务结构，三处换算必须写对：

  • x / y：originX/originY 默认为 'left'/'top' 时，obj.left / obj.top 就是包围盒左上角的画布坐标，可直接当 x/y；若项目统一把 origin 设为 'center'，必须减去 getScaledWidth() / 2 与 getScaledHeight() / 2 修正，否则导出结果整体偏移半个宽高；
  • w / h：用户拖手柄改的是 scaleX/scaleY，实际占位必须用 getScaledWidth() / getScaledHeight()；
  • label：用一个 Map 维护"Rect 到 IText"的对应关系，导出时取 label.text——用户双击改过文字后，text 属性已是最新值。

旋转角度在本业务模型中未纳入；如需支持，在导出结构里补充 angle: Math.round(obj.angle) 即可。

这套换算反过来就是导入：业务 JSON 里的 x/y/w/h 乘回 scaleX/scaleY、new Rect() 后 set 坐标与文字，即可把存档还原回画布场景，存档恢复与多人协作同步走的正是这条逆向链路。

键盘删除的守卫链 ​

Delete/Backspace 删除选中项，监听必须绑在 window 上（fabric 画布不自动持有键盘焦点），且要带上两层守卫：正在编辑标签文字时不劫持按键（判断 activeObject.isEditing），否则用户无法用退格删除字符；事件源是 INPUT、TEXTAREA 或 contentEditable 时不劫持，避免干扰页面级 UI（比如站点搜索框）。onBeforeUnmount 里移除监听并 dispose 画布，两项缺一不可。

核心 API 与原理 ​

  • FabricImage.fromURL(url)：v6 返回 Promise，第二个参数可传 crossOrigin 等加载选项；
  • canvas.sendObjectToBack(obj)：v6 层级 API（取代 v5 的 sendToBack），把对象压到最底层；
  • 选中样式定制：borderColor（选中框颜色）、cornerColor（手柄填充）、cornerStrokeColor（手柄描边）、cornerStyle（'circle' 圆形手柄）、cornerSize（手柄尺寸）、transparentCorners: false（手柄不透明，深色底图上更清晰）；
  • strokeUniform: true：非等比拉伸时描边粗细保持恒定，否则虚线框被拉扁后粗细突变；
  • active.isType('ActiveSelection', 'activeselection')：判断多选组合（v6 静态类型为 'ActiveSelection'，兼容小写旧值），配合 getObjects() 拆开逐一删除；
  • canvas.dispose()：释放离屏画布与监听，与 window 键盘监听的解绑同属卸载清理清单。

完整代码示例 ​

拖动移动 / 手柄缩放旋转 / 双击标签修改文字 / 按 Delete 或 Backspace 删除选中（支持 Shift 多选）

点击「导出标注」查看业务 JSON

试试：点"添加标注框"后拖动、缩放、旋转；双击"标注 1"改成有业务含义的文字；框选或 Shift 多选后按 Delete 删除；最后点"导出标注"，核对 JSON 里的 x/y/w/h 与画布中框的实际位置尺寸是否完全一致。

核心代码（与上方演示一致的精简版，可直接放入任意 SFC 的 script setup）：

js
// 文件: docs/.vitepress/components/fabric/FabricAnnotate.vue
// 说明：以下为 script setup 核心逻辑；模板部分是一个演示卡片，
// 包含三个操作按钮、canvas 画布、操作提示与业务 JSON 输出区
import { ref, onMounted, onBeforeUnmount } from 'vue'

let fabricCanvas = null
let fabricLib = null

const canvasRef = ref(null)
const wrapRef = ref(null)
const jsonOutput = ref('')

// 用 Map 维护「标注框 Rect -> 标签 IText」：刻意不合成 Group，见正文取舍说明
const labelMap = new Map()
let labelSeq = 1

// 离屏 canvas 程序化生成 800x500"照片"（渐变天空 + 太阳 + 山形），不依赖外部资源
function makePhoto() {
  const off = document.createElement('canvas')
  off.width = 800
  off.height = 500
  const ctx = off.getContext('2d')
  const sky = ctx.createLinearGradient(0, 0, 0, 500)
  sky.addColorStop(0, '#7dd3fc')
  sky.addColorStop(1, '#fef3c7')
  ctx.fillStyle = sky
  ctx.fillRect(0, 0, 800, 500)
  ctx.fillStyle = '#fbbf24'
  ctx.beginPath()
  ctx.arc(620, 118, 56, 0, Math.PI * 2)
  ctx.fill()
  return off.toDataURL('image/png')
}

// 添加一组标注：虚线框 + 标签，两个独立对象
function addBox() {
  const { Rect, IText } = fabricLib
  const left = 40 + Math.random() * Math.max(fabricCanvas.width - 240, 1)
  const top = 40 + Math.random() * Math.max(fabricCanvas.height - 180, 1)
  const rect = new Rect({
    width: 180,
    height: 120,
    fill: 'rgba(37, 99, 235, 0.06)', // 近透明填充，不遮挡底图
    stroke: '#2563eb',
    strokeWidth: 2,
    strokeDashArray: [6, 4],
    strokeUniform: true, // 拉伸后描边粗细恒定
    borderColor: '#2563eb', // 以下为选中样式定制
    cornerColor: '#ffffff',
    cornerStrokeColor: '#2563eb',
    cornerStyle: 'circle',
    cornerSize: 10,
    transparentCorners: false
  })
  rect.set({ left, top })
  const label = new IText('标注 ' + labelSeq, { fontSize: 16, fill: '#1d4ed8' })
  labelSeq += 1
  label.set({ left, top: Math.max(top - 24, 4) }) // 标签默认悬于框上方
  labelMap.set(rect, label)
  fabricCanvas.add(rect)
  fabricCanvas.add(label)
  fabricCanvas.setActiveObject(rect)
  fabricCanvas.requestRenderAll()
}

// 删除选中：Shift 多选时 active 是 ActiveSelection，拆开逐一删除
function removeSelected() {
  const active = fabricCanvas.getActiveObject()
  if (!active) return
  const targets = active.isType('ActiveSelection', 'activeselection')
    ? active.getObjects()
    : [active]
  targets.forEach((obj) => {
    labelMap.delete(obj) // 删的是标注框本身
    labelMap.forEach((labelObj, rect) => {
      if (labelObj === obj) labelMap.delete(rect) // 删的是标签时清理映射
    })
    fabricCanvas.remove(obj)
  })
  fabricCanvas.discardActiveObject()
  fabricCanvas.requestRenderAll()
}

// 导出业务 JSON：只保留标注框的几何信息与标签文字
function exportAnnotations() {
  const result = []
  fabricCanvas.getObjects().forEach((obj) => {
    if (!obj.isType('Rect')) return // 底图 Image 与标签 IText 在此被过滤
    // 换算说明：
    // 1) originX/originY 默认 'left'/'top'，obj.left/top 即左上角画布坐标，直接当 x/y；
    //    若全局 origin 为 'center'，需减去 getScaledWidth()/2、getScaledHeight()/2 修正
    // 2) 手柄缩放改的是 scaleX/scaleY，实际宽高必须用 getScaledWidth/getScaledHeight
    // 3) 旋转角度未纳入本业务模型，需要时补 obj.angle 字段
    result.push({
      x: Math.round(obj.left),
      y: Math.round(obj.top),
      w: Math.round(obj.getScaledWidth()),
      h: Math.round(obj.getScaledHeight()),
      label: labelMap.has(obj) ? labelMap.get(obj).text : ''
    })
  })
  jsonOutput.value = JSON.stringify(result, null, 2)
}

// 键盘删除：两层守卫——文本编辑态不劫持；焦点在输入框时不劫持
function onKeydown(e) {
  if (e.key !== 'Delete' && e.key !== 'Backspace') return
  const active = fabricCanvas.getActiveObject()
  if (active && active.isEditing) return
  const t = e.target
  if (t && (t.tagName === 'INPUT' || t.tagName === 'TEXTAREA' || t.isContentEditable)) return
  e.preventDefault()
  removeSelected()
}

onMounted(async () => {
  const { Canvas, Rect, IText, FabricImage } = await import('fabric')
  if (!canvasRef.value || !wrapRef.value) return // 动态加载期间组件可能已卸载
  fabricLib = { Rect, IText }

  const width = Math.min(wrapRef.value.clientWidth || 640, 640)
  const height = Math.round(width * 0.625) // 与底图 800x500 等比（8:5）
  fabricCanvas = new Canvas(canvasRef.value, { width, height, backgroundColor: '#ffffff' })

  // 底图：fromURL 返回 Promise；铺满用 scale 而非改宽高（改宽高会裁切源图）
  const img = await FabricImage.fromURL(makePhoto())
  if (!fabricCanvas) return // await 期间组件可能已被卸载并 dispose
  img.set({
    scaleX: fabricCanvas.width / img.width,
    scaleY: fabricCanvas.height / img.height,
    selectable: false, // 底图不可选中
    evented: false // 底图不响应事件，点击穿透到标注框
  })
  fabricCanvas.add(img)
  fabricCanvas.sendObjectToBack(img) // v6 层级 API：sendObjectToBack 取代 sendToBack

  window.addEventListener('keydown', onKeydown)
})

onBeforeUnmount(() => {
  // 监听与画布双清理，VitePress 是 SPA，漏一项都会泄漏
  window.removeEventListener('keydown', onKeydown)
  if (fabricCanvas) {
    fabricCanvas.dispose()
    fabricCanvas = null
  }
})

最佳实践与常见坑 ​

  • 底图必须 selectable: false 加 evented: false。只设 selectable 不够：evented 控制能否成为事件目标，漏掉的话点击仍会"选中底图"，标注框永远点不到。这两个开关是分层交互的基石。
  • await FabricImage.fromURL() 之后要判空画布。VitePress 是 SPA，动态 import 与图片加载之间存在竞态——用户可能在加载完成前就切走路由，此时画布已被 dispose，继续 add 会报错。每个 await 之后校验实例是否存在是固定写法。
  • Backspace 与文本编辑的按键冲突。IText 编辑态下按退格是为了删字符，window 层的 keydown 却会先触发；不判断 active.isEditing 就 preventDefault，用户会发现标签"退格删字变成删标注"。输入框守卫同理。
  • 非等比缩放后虚线描边粗细突变。Rect 被水平拉长后，默认描边会跟随拉伸变形，strokeUniform: true 让描边以屏幕像素恒定粗细渲染，标注框才始终保持视觉一致。
  • 导出换算与 origin 设置强相关。团队若把默认 origin 统一改为 'center'，导出代码里的 x/y 却按 'left' 语义取值，数据会整体偏移半宽半高；坐标换算逻辑必须与项目 origin 约定成对出现，并在代码注释里写清前提。
  • selection:created 的 opt.selected 是数组——前面 4.2 已经强调过，本节的删除逻辑同样按此处理：ActiveSelection 拆开逐一删除，否则多选时只能删掉一个。
  • 随机初始位置要按运行时画布尺寸夹紧。画布宽度是按容器动态确定的，写死坐标范围会在窄屏上把标注框生成到画布外；组件里用 canvas.width / canvas.height 动态计算随机区间就是这个原因。
  • 标注数据与底图数据要分离存档。toJSON() 会把底图的完整 dataURL 塞进 JSON，几十 KB 的照片会膨胀数倍且随存档数量线性增长；像本例一样只导出业务字段，底图单独存储，是标注类产品的标准做法。

小结 ​

本节要点：标注工具的骨架是"底图退出交互、标注独占选中、标签双击编辑、导出只留业务字段"四层分工；底图用离屏 canvas 生成 dataURL 后经 FabricImage.fromURL（v6 返回 Promise）加载，用 scaleX/scaleY 铺满并用 selectable/evented 关闭交互；框与标签保持独立对象是简化取舍，Group 才是正式产品的组合方案；导出换算的关键是 origin 语义与 getScaled 系列尺寸；键盘删除需要 isEditing 与输入框两层守卫。至此 Fabric.js 章节完结，下一篇 快速上手与核心概念 将进入 ECharts 的声明式图表世界。
