4.1 核心对象模型 ​

在 Canvas 实战一章里，我们为手写的图形逐个实现过命中检测：矩形要算包围盒、圆要算距离，图形一旦旋转缩放，代码量与出错率都会陡增。Fabric.js 正是为消掉这部分成本而生——它在原生 Canvas 之上维护一棵"保留模式"的对象树，把选中、拖拽、缩放、旋转、序列化做成开箱即用的能力。本节建立对象模型认知，是后续交互与实战两节的地基。

概念解析 ​

Fabric.js 是什么 ​

Fabric.js 是构建在原生 Canvas 2D 之上的二维绘图库，核心思路是"保留模式"（Retained Mode）：你不再调用一条条绘制指令，而是创建一个个对象（矩形、圆、文本、图片），交给 Canvas 集中管理；渲染、命中、变换都围绕这棵对象树进行。

对比 三种方式画柱状图 中的原生 Canvas 方案：立即模式下画完即忘，想改一个柱子的高度只能整体重画；fabric 里改一个对象属性、调一次重绘即可，对象之间还能比较、过滤、组合。这就是"图形即对象"带来的工程红利。

本教程基于 v6（当前 6.9）：v6 是一次大版本重构，改为 ESM 具名导出，loadFromJSON 等异步 API 改为 Promise，部分 API 更名，与网上大量 v5 教程不兼容。阅读社区代码时先确认版本，本章所有 API 均以 v6 为准。

与原生 Canvas 的关系 ​

一个关键认知：fabric 并没有替换 Canvas 的渲染机制。它内部仍然持有一个真实的 canvas 元素，仍然在一次次的 renderAll 里全量重绘所有对象——本质性能特征与原生 Canvas 相同（大量对象时同样是全量重绘的代价）。

fabric 接管的是四层工程化负担：

  • 对象树管理：增删、层级、遍历、按属性过滤；
  • 命中检测：旋转缩放后的包围盒判断全部内置；
  • 变换控制：选中框、8 个缩放手柄、旋转点自动渲染并响应；
  • 序列化：对象树与 JSON / 位图 / SVG 互转。

实现上有个值得了解的细节：交互用的 Canvas 会创建上下两层画布，下层画对象，上层画选中框、手柄与自由绘制笔迹，两层互不污染——这就是为什么选中态不会把业务画面"画脏"。

两种模式的职责分工对照：

工程负担原生 CanvasFabric.js
图形状态自行记录坐标与属性对象树天然持有
命中检测手写包围盒、距离判断，旋转后还要做坐标变换内置，含旋转缩放后的精确判断
重绘时机手动管理脏标记与重画属性变更后 requestRenderAll()
选中框与手柄完全手写自动渲染并响应拖拽
存档恢复自定义序列化结构toJSON / loadFromJSON 直接可用

这也是为什么在 Canvas 实战 里"做一个能拖动的图形"需要上百行状态管理，而 fabric 里只需要一个 add()。

典型应用场景 ​

  • 图片标注工具（本章 4.3 实战的主题）；
  • 海报、名片、商品图在线设计器；
  • 轻量白板与流程图节点编辑；
  • 需要"编辑 + 导出图片 + 存档恢复"组合能力的任何场景。

只要需求里出现"用户要拖动、缩放某个图形"，原生 Canvas 的手写成本就会快速超过引入 fabric 的体积成本。

核心 API 与原理 ​

核心类一览 ​

类说明
Canvas画布容器，持有对象树与交互层，所有事件从它注册
Rect / Circle / Ellipse / Line / Polygon / Path基础形状对象
IText可点击编辑的文本（不自动换行）
Textbox固定宽度、自动换行的可编辑文本
Group把多个对象组合为一个整体
FabricImage图片对象（v6 从 fabric.Image 更名而来，老代码需同步修改）
PencilBrush自由绘制画笔（4.2 节展开）

v6 全部支持具名导出，因此推荐用动态 import 按需解构：const { Canvas, Rect, IText } = await import('fabric')。

IText 与 Textbox 都支持双击进入编辑，差别在排版能力：IText 不自动换行，适合短标签（标注名、编号）；Textbox 有固定宽度，超出自动折行并撑高，适合段落文案。二者的光标、选区、退格等编辑行为完全由 fabric 内部处理，无需自己叠加 input 元素。

公共属性系统 ​

所有图形对象继承自 FabricObject，共享同一套属性协议：

  • 几何：left、top、width、height、angle；
  • 变换：scaleX、scaleY、flipX、flipY；
  • 外观：fill、stroke、strokeWidth、strokeDashArray、opacity；
  • 行为开关：selectable（能否被选中）、evented（能否成为事件目标）、visible（是否渲染）。

坐标原点是最容易困惑的点：left/top 的语义取决于 originX/originY，v6 默认取值是 'left'/'top'，即坐标指向包围盒左上角；但 fabric 内部的旋转与缩放始终围绕对象中心计算，官方也已把 left/top 起点标记为过渡方案，建议新项目统一设为 'center'。取舍参考：

  • 用默认 left/top：与鼠标坐标直观对齐，"拖到哪儿 left 就是几"，适合标注框这类框选语义；
  • 用 center：围绕中心的布局、对称与旋转补偿计算更省心，代价是接受"位置属性是中心点"的心智模型；
  • 切换 origin 后，同一视觉位置对应的 left/top 数值会改变，序列化数据迁移时必须统一，否则加载后整体偏移。

另一个高频换算：手柄缩放改变的是 scaleX/scaleY，width/height 不变，所以实际占位尺寸要用 getScaledWidth() / getScaledHeight() 计算，而不是直接读宽高。

origin 的实际影响用代码看最直观：

js
// 同一个位置，origin 语义不同，left/top 表达完全不同
const rect = new Rect({ width: 100, height: 60, left: 200, top: 150 })
// 默认 originX/originY 为 'left'/'top'：左上角在 (200, 150)，中心在 (250, 180)

// 直接改 origin：left/top 数值不变但语义变成"中心点"，对象会视觉跳变
rect.set({ originX: 'center', originY: 'center' })

// 保持视觉位置换 origin 的正确姿势：setPositionByOrigin 按目标原点反算
rect.setPositionByOrigin(new Point(250, 180), 'center', 'center')

序列化与导出 ​

一句话版：

  • canvas.toJSON()：整棵对象树序列化为 JSON，是保存、撤销栈、协作同步的基础；
  • canvas.loadFromJSON(json)：把 JSON 载回画布，v6 返回 Promise（v5 是回调风格），完成后建议手动 requestRenderAll()；
  • canvas.toDataURL()：导出位图 PNG，可直接下载或回传服务端；
  • canvas.toSVG()：导出矢量 SVG，可无损进入设计工具二次加工。

toJSON() 的输出结构长这样（toDataURL 与 toSVG 则直接产出图片数据）：

json
{
  "version": "6.9.1",
  "objects": [
    {
      "type": "Rect",
      "left": 60,
      "top": 60,
      "width": 120,
      "height": 80,
      "fill": "rgba(16, 185, 129, 0.85)",
      "angle": 0,
      "scaleX": 1,
      "scaleY": 1,
      "originX": "left",
      "originY": "top"
    }
  ],
  "background": "#f8fafc"
}

两个版本差异值得记录：v6 序列化的 type 是大写类名（v5 是小写，反序列化时两者都兼容）；originX/originY 会随对象一起写出，跨版本或跨 origin 策略迁移数据时留意这两个字段。

对象层级 ​

add() 入树、remove() 出树、getObjects() 取列表；层级调整在 v6 更名为 bringObjectToFront() / sendObjectToBack()——v5 的 bringToFront / sendToBack 已被移除，网上老代码直接照抄会报错。底图压底、标注置顶，就是这两个方法最典型的用法：

js
canvas.add(obj) // 入树，默认追加到顶层
canvas.sendObjectToBack(img) // 压到最底层：底图的固定位置
canvas.bringObjectToFront(mark) // 提到最顶层：新标注的固定位置
canvas.remove(obj) // 出树，同时触发 object:removed 事件

核心代码（与上方演示一致的精简版，可直接放入任意 SFC 的 script setup）：

js
// 文件: docs/.vitepress/components/fabric/FabricObjects.vue
// 说明：以下为 script setup 核心逻辑；模板部分是一个演示卡片，
// 包含五个操作按钮、canvas 画布、只读属性面板与 JSON 输出区
import { ref, onMounted, onBeforeUnmount } from 'vue'

// fabric 依赖 window：只能在 onMounted 内动态 import，实例挂普通变量
let fabricCanvas = null
let fabricLib = null

const canvasRef = ref(null)
const wrapRef = ref(null)
const info = ref({ type: '未选中', left: '-', top: '-', angle: 0, scaleX: 1, scaleY: 1 })
const historyStack = [] // 撤销栈：每帧稳定状态存一份 toJSON 快照

function refreshPanel(obj) {
  if (!obj) {
    info.value = { type: '未选中', left: '-', top: '-', angle: 0, scaleX: 1, scaleY: 1 }
    return
  }
  info.value = {
    type: obj.type,
    left: Math.round(obj.left),
    top: Math.round(obj.top),
    angle: Math.round(obj.angle),
    scaleX: obj.scaleX.toFixed(2),
    scaleY: obj.scaleY.toFixed(2)
  }
}

// 每次压栈都全量序列化；限制栈深避免长会话内存膨胀
function pushHistory() {
  historyStack.push(fabricCanvas.toJSON())
  if (historyStack.length > 30) historyStack.shift()
}

// 撤销：弹出当前帧，把前一帧载回画布
async function undo() {
  if (historyStack.length <= 1) return
  historyStack.pop()
  // v6 关键差异：loadFromJSON 返回 Promise（v5 是回调），完成后需手动重绘
  await fabricCanvas.loadFromJSON(historyStack[historyStack.length - 1])
  fabricCanvas.requestRenderAll()
  refreshPanel(null)
}

function addShape(kind) {
  const { Rect, Circle, IText } = fabricLib
  const left = 50 + Math.random() * 180
  const top = 40 + Math.random() * 100
  let obj
  if (kind === 'rect') {
    obj = new Rect({ width: 130, height: 84, fill: 'rgba(96,125,255,0.85)', rx: 8, ry: 8 })
  } else if (kind === 'circle') {
    obj = new Circle({ radius: 42, fill: 'rgba(255,112,67,0.85)' })
  } else {
    obj = new IText('双击可编辑', { fontSize: 22, fill: '#1e293b' })
  }
  // left/top 的语义取决于 originX/originY，v6 默认左上角定位
  obj.set({ left, top })
  fabricCanvas.add(obj)
  fabricCanvas.setActiveObject(obj)
  fabricCanvas.requestRenderAll()
  pushHistory()
}

function exportJSON() {
  return JSON.stringify(fabricCanvas.toJSON(), null, 2)
}

onMounted(async () => {
  const { Canvas, Rect, Circle, IText } = await import('fabric')
  if (!canvasRef.value || !wrapRef.value) return // 动态加载期间组件可能已被卸载
  fabricLib = { Rect, Circle, IText }

  // 按容器实际宽度初始化（上限 640），避免 CSS 拉伸导致指针坐标偏移
  const width = Math.min(wrapRef.value.clientWidth || 640, 640)
  fabricCanvas = new Canvas(canvasRef.value, {
    width,
    height: Math.round(width * 0.625),
    backgroundColor: '#f8fafc'
  })

  // 选中三事件 + 变换结束事件，共同驱动面板刷新与撤销压栈
  fabricCanvas.on('selection:created', () => refreshPanel(fabricCanvas.getActiveObject()))
  fabricCanvas.on('selection:updated', () => refreshPanel(fabricCanvas.getActiveObject()))
  fabricCanvas.on('selection:cleared', () => refreshPanel(null))
  fabricCanvas.on('object:modified', () => {
    refreshPanel(fabricCanvas.getActiveObject())
    pushHistory()
  })
})

onBeforeUnmount(() => {
  // SPA 路由切换组件销毁：不 dispose 会泄漏离屏画布与事件监听
  if (fabricCanvas) {
    fabricCanvas.dispose()
    fabricCanvas = null
  }
})

最佳实践与常见坑 ​

  • loadFromJSON 在 v6 返回 Promise。v5 教程的 loadFromJSON(json, cb) 回调写法在 v6 会静默失效——不报错但后续代码拿不到加载完成的时机。统一 await 之后 requestRenderAll()，撤销、存档恢复才有确定时序。
  • 判断占位尺寸永远用 getScaledWidth / getScaledHeight。用户拖手柄改的是 scaleX/scaleY，width/height 不变；边界限制、碰撞判断、导出换算若直接读宽高，缩放后全部失准。
  • 层级 API 已经改名。v6 用 bringObjectToFront(obj) / sendObjectToBack(obj)，v5 的 bringToFront/sendToBack 被彻底移除；从社区抄代码先确认版本，否则运行时报 TypeError。
  • 自定义属性默认不进序列化结果。toJSON 只输出内置属性，挂在对象上的业务字段（标注 id、关联数据）会被静默丢弃；要么在 toObject / toJSON 时传入 propertiesToInclude，要么导出时单独映射。"看起来保存了"却在恢复后丢数据，是这类问题最隐蔽的形态。
  • originX/originY 与序列化要统一。同一对象在 'left' 与 'center' 两种 origin 下 left/top 数值不同；换 origin 后直接加载旧 JSON 会整体位移，存档升级时需要做一次换算迁移。
  • IText 与 Textbox 按场景选型。IText 不自动换行，适合短标签（标注名、编号）；Textbox 固定宽度自动换行，适合段落文案。选错的表现是"长文本撑出画布"或"标签被换行拆成多行"。
  • dispose() 不可省略。VitePress 是 SPA，路由离开后组件销毁，fabric 的离屏画布、DOM 包装层与事件监听不会自动回收，必须在 onBeforeUnmount 里显式 dispose。

小结 ​

本节要点：fabric 是原生 Canvas 之上的保留模式对象树，渲染本质仍是 renderAll 全量重绘，它接管的是对象管理、命中检测、变换控制与序列化四层工程负担；所有对象共享 left/top/angle/scale 等公共属性，坐标语义由 originX/originY 决定，实际尺寸要用 getScaled 系列方法；toJSON 与 loadFromJSON（v6 返回 Promise）构成存档与撤销的底座；v6 的层级 API 已更名为 bringObjectToFront / sendObjectToBack。下一节 4.2 交互与编辑器能力 将深入变换控件、事件体系与自由绘制，把"编辑器手感"拆开讲透。
